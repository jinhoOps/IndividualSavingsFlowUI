# 계좌 맵 생성·편집 입력 설계

2026-09-12. 사용자 요청: Main의 마법사와 편집 경험을 기준으로 계좌 맵의 최초 생성과 편집을 재구성한다. 이 문서는 [Product PRD](../ways-of-work/plan/isf-rebuild/connected-financial-planning-workspace/prd.md)와 [계좌 흐름 계약](../superpowers/specs/2026-09-04-account-map-planned-account-flow-design.md)의 입력 UI를 구체화한다.

## 관찰한 문제

390px 화면에서 목적 다섯 개와 별도의 입력창이 길게 나열되고, 설정 하단의 네 버튼이 내용을 가렸다. 연결된 계좌 이름은 목록에 나타나지 않았다. 편집 체크박스가 일반 입력 너비를 상속해 설명이 좁게 잘렸다. 계좌 정보와 목적 배정, 이체 계획을 수정하는 진입점도 분산되어 있었다.

## 최초 생성

1. **월 계획 확인**: Main의 다섯 금액을 읽기 전용 행으로 요약한다. 금액 수정은 기존 Main 소유 편집기로 요청한다.
2. **목적별 계좌 연결**: 수입 → 주거 → 생활비 → 저축 → 투자 순서로 한 목적을 질문한다. 상단 목적 버튼으로 재방문할 수 있다. 현재 목적의 월 기준, 실제 계좌 이름, 연결 후 배정액을 같은 질문 카드에서 확인한다. 수입 계좌 연결은 완료의 필수 조건이며 다른 목적은 나중에 연결할 수 있다. 0원인 지출·저축·투자 목적에도 명시적 계좌 연결을 허용한다.
   - 이미 등록한 계좌를 재사용하거나 새 계좌를 추가한다. 은행·증권·현금 선택, 은행 목록/기관 직접 입력, 지도 표시 이름 순서다. 계좌번호는 수집하지 않는다.
   - 첫 계좌에 월 금액을 배정하고 추가 계좌에는 배정할 월 금액을 받는다. 설정 중에도 `배정 금액 수정`으로 수정·연결 제거·나머지 자동 계산을 제공한다.
   - 목적을 오가도 목적별 작성 중 입력을 보존한다. 계정 사용 시 기존 recovery 저장을 재사용한다. 성공한 연결만 draft에 반영하며 실패·충돌 입력은 보존한다.
3. **이체 계획**: 계좌 간 이동이 필요할 때만 제안을 적용하거나 직접 입력한다. 편집 중에는 해당 양식에 집중하고 다음 단계 이동을 잠근다. 출발·도착·고정 금액/남은 금액 전부·상태와 반영할 계획 요약을 표시한다. 제안은 사용자 선택 없이 저장하지 않는다. 같은 검토 화면에서 제안 하나를 수락해도 나머지 제안은 유지한다. 기준 계좌·목적이 바뀌거나 직접 흐름을 편집하면 이전 제안을 비운다.
4. **최종 확인**: 완료 지도와 같은 계산·그래프를 보여준다. 계좌·배정 또는 이체 계획 수정으로 바로 돌아갈 수 있다. 수입 연결과 초과 배정 문제를 해소한 뒤 `지도 만들기`로 applied에 반영한다. 부족·미배정 경고는 실제 잔액이 아닌 월 계획임을 설명한다. 설정의 이동 버튼은 본문 뒤에 두어 입력 양식과 지도를 덮지 않는다.

## 완료 후 편집

- 지도 선택 편집을 유지하고, `계좌 맵 편집`으로 세 편집 그룹에 바로 접근한다. 모바일은 Main과 같은 하단 고정 진입점을 제공한다.
- **목적별 배정**: 목적·월 기준·연결 계좌·미배정 또는 초과 금액을 한 행에 표시한다. 행을 누르면 바로 배정 편집기로 진입한다.
- **계좌 정보**: 계좌 이름과 기관을 보고 직접 수정하거나 보관한다. 새 계좌는 사용할 목적에서 연결한다.
- **계좌 간 흐름**: 출발 → 도착과 월 금액 또는 남은 금액 전부 규칙을 보고 직접 수정한다. 흐름이 없어도 추가 방법을 안내한다.
- 모바일은 bottom sheet, 768px 이상은 우측 panel이다. 배경은 inert, 본문만 스크롤하고 취소·저장은 한 줄이다. 양식 변경이 없으면 저장은 비활성이다. 미저장 변경을 닫을 때는 계속 편집/변경 버리고 닫기를 제공한다. 실패·충돌에서는 입력을 보존하고 재시도한다. 닫은 뒤 진입점으로 focus를 복원한다.
- 금액 입력은 기존 FormattedMoneyInput을 사용한다. 여러 배정액의 빠른 조정은 마지막으로 편집한 금액 행에서만 표시하고, 자동 계산 항목은 직접 금액 입력과 구분한다. 체크박스와 radio는 일반 텍스트 입력의 너비 규칙을 적용받지 않는다.

## 데이터 경계

저장 schema, location ID, 기존 draft의 큰 단계 네 가지, import/export와 revision 규칙은 변경하지 않는다. Account Map은 `workspace.locations`와 `workspace.accountMap`만 갱신한다. Main·Simulation·Portfolio에 write-back하지 않는다. 목적 연결의 remainder와 계좌 간 sweep은 구분한다. 계좌 보관·복원과 충돌 복구는 기존 command를 사용한다.

## 인수 검증

- 빈 계좌 맵에서 생성 → 수입/생활비/투자 연결 → 이체 계획 → 검토 → 완료 → 재로드.
- 목적 재방문과 작성 중 입력 보존, 설정 중 배정 수정, 0원/생략 가능한 목적.
- 완료된 계좌 정보·배정·이체의 수정, 취소/미저장 닫기, 저장 실패/충돌 후 복구.
- 390px·768px·desktop 및 짧은 viewport에서 가로 overflow, overlay containment, focus trap/복원, 44px 조작 영역, 지도 표시.
- 타입 검사, Account Map 단위 테스트, 전체 CI 검사, 관련 Playwright 및 전체 E2E, 프로덕션 Vite build와 diff 검사. 실행 결과는 완료 인계에서 별도로 보고하며 이 문서는 테스트 통과를 미리 주장하지 않는다.
