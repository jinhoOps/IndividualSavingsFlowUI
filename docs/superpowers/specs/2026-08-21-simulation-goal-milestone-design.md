# Simulation 목표 도달 요약 설계

## 문서 상태

- 승인일: 2026-08-21
- 범위: Simulation의 결과 헤드라인, 최초 설정 질문, 목표 도달 계산과 Simulation draft 저장 계약
- 선행 문서: [Simulation 결과 중심 경험 재설계](2026-08-03-simulation-experience-redesign-design.md)
- 우선순위: 이 문서는 선행 문서의 최초 설정 2단계, 결과 핵심 문장, `CompoundSimulationDraft` 계약을 아래 범위에서 대체한다. Main read-only 경계, 기존 복리 식, 그래프·비교값과 기간 조작 계약은 유지한다.

## 목적

기존 결과 제목은 사용자가 선택한 기간 뒤의 총액을 말한다. 이를 사용자의 다음 자산 이정표와 연결해, 현재 조건에서 목표 금액에 처음 도달할 예상 시점을 월 단위로 알려준다. 그래프는 계속 사용자가 선택한 기간의 결과를 보여주므로, 목표 안내와 그래프 탐색은 의도적으로 분리한다.

## 비목표

- 목표 금액별 투자 조언, 상품 추천 또는 목표 달성 보장
- 30년보다 긴 기간의 외삽
- Main write-back, 별도 목표 저장소, 여러 목표 목록
- 그래프의 기간·점 밀도·비교 기준선 변경

## 사용자 흐름

### 최초 설정

질문 화면은 한 번에 한 가지 결정과 한 가지 주 입력만 보인다.

1. `지금 모아둔 투자금이 있나요?`
   - `있어요`를 선택하면 현재 모아둔 투자금을 입력한다.
   - `없어요`는 시작 자산 0원을 적용한다.
2. 시작 자산이 2억 원 이상일 때만 `다음에는 얼마를 모으고 싶나요?`를 별도 화면으로 표시한다.
   - 목표 금액 하나만 입력한다.
   - 목표는 시작 자산보다 큰 안전한 정수 원화여야 한다.
3. `매년 어느 정도 수익을 기대하나요?`
   - 기간 control을 포함하는 결과 화면의 `SimulationControls`를 재사용하지 않는다. 기대수익률 preset·직접 입력과 비자문 안내만 담당하는 온보딩 전용 component를 둔다.
   - 기존 5%, 9%, 13%, 직접 입력 조작을 유지한다.
   - 기간 입력, 실시간 결과 문장, 미리보기 그래프와 계산 조건이라는 복수 주제는 이 단계에서 제거한다.
   - 결과 보기 후 기본 기간 5년의 결과 화면으로 간다.

목표 금액 결정 규칙은 다음과 같다.

| 시작 자산 | 목표 |
| --- | --- |
| 8천만 원 미만 | 1억 원 자동 지정 |
| 8천만 원 이상, 2억 원 미만 | 2억 원 자동 지정 |
| 2억 원 이상 | 사용자에게 직접 질문 |

`8천만 원`, `2억 원` 경계는 각각 상위 구간에 포함한다.

### 재방문과 다시 설정

- 목표가 있는 저장된 draft는 결과 화면으로 바로 진입한다.
- 목표 미완료 draft는 결과 화면을 거치지 않는다. bootstrap은 `goal-required` 상태로 분기하고, 시작 자산·기간·수익률·금리·금액 모드를 보존한 채 목표 질문 화면만 표시한다.
- 다시 설정은 Simulation draft만 지우고 전체 최초 설정을 다시 시작한다. 2억 원 이상 사용자는 그 과정에서 목표를 다시 정한다.
- 2026-09-11 사용자 승인 확장으로 결과 하단에서 목표를 직접 조정한다. 아래 확장 계약을 따른다.

### 기존 저장 데이터

- workspace parser는 Simulation slice를 현재 schema로 검증하기 전에 v2 이하 Simulation draft를 v3로 이관한다. 이관 실패만 workspace 손상으로 처리하며, Main·Portfolio·locations·Account Map slice는 이 과정에서 변경하지 않는다.
- schema v2 이하 draft가 시작 자산 2억 원 미만이면 규칙에 따른 목표를 보완해 v3 draft로 저장한다.
- 시작 자산이 2억 원 이상인 v2 이하 draft는 기간·수익률·금리·금액 모드를 보존한다. 다만 `targetAmountWon: null`인 목표 미완료 상태로 이관되어 목표 질문만 한 번 거친 뒤 결과 화면에 들어간다.
- 손상된 목표나 시작 자산과 같거나 작은 목표는 유효 draft로 취급하지 않는다. 기존의 손상 draft 복구 흐름을 사용한다.

## 데이터 계약

`SIMULATION_SCHEMA_VERSION`을 3으로 올리고 Simulation 소유 draft에 다음 필드를 추가한다.

```ts
targetAmountWon: number | null;
```

- 정상 결과 draft의 `targetAmountWon`은 양의 안전 정수이고 `initialInvestmentWon`보다 크다.
- `null`은 schema v2 이하에서 이관됐으나 2억 원 이상 사용자의 목표 질문이 아직 끝나지 않았다는 전이 상태에만 허용한다.
- Main source, Main 저장, workspace 밖 별도 key와 다른 앱 slice는 변경하지 않는다.
- 저장·가져오기·복원은 workspace parser가 Simulation slice의 새 schema로 먼저 이관·검증한 뒤, 전체 workspace 계약을 검증한다. Simulation 이관은 다른 slice를 변경하지 않는다.

## 목표 도달 계산

### 탐색 범위와 기준

- 목표 입력값의 임의 금액 상한을 두지 않는다. 탐색 상한은 현재 제품 계약의 30년(360개월)이다.
- 사용자 수익률, 월 저축·투자, 기준금리, 물가 차이와 시작 자산을 기존 월 말 납입 복리 식에 그대로 적용한다.
- 1개월부터 360개월까지 계산하고, 현재 선택한 `amountMode`의 현재 계획 금액이 목표 이상이 되는 첫 월을 찾는다.
- 명목 모드에서는 명목 1억/2억/사용자 목표까지, 실질 모드에서는 오늘의 구매력 기준 실질 1억/2억/사용자 목표까지의 기간을 각각 안내한다.
- 그래프는 `draft.years`의 연 단위 결과만 계속 표시한다. 목표 도달 계산 때문에 기간을 자동 변경하거나 그래프 점을 월 단위로 늘리지 않는다.

계산 함수는 그래프 projection과 같은 월별 잔액 규칙을 한 곳에서 재사용하거나, 그 동치가 unit test로 입증되는 순수 domain 경계에 둔다.

### 결과 문구

도달한 경우 헤드라인은 다음 형식이다.

- `1억 원을 모으려면 3년 7개월이 걸려요`
- 12개월의 배수는 `8년`만, 12개월 미만은 `9개월`만 표시한다.

360개월 안에 도달하지 못하면 다음 형식이다.

- `현재 조건으로는 30년 안에 5억 원에 도달하기 어려워요`

목표와 시작 자산의 관계는 입력 단계에서 보장하므로, 결과 화면에 이미 도달했다는 별도 문구는 만들지 않는다. 헤드라인 아래 조건 한 줄은 계속 `월 저축 · 투자 · 연 수익률`을 설명한다.

## UI·접근성

- 목표 질문은 기존 시작 자산 질문과 같은 `Surface`, focus 이동, primary action과 오류 표현을 사용한다.
- 라벨, input mode, 오류 연결과 제출 버튼 disabled 상태로 목표가 시작 자산보다 커야 함을 명확히 한다. 숫자만 제거하지 않고 오류 문구로 이유를 알려준다.
- 수익률 질문은 금융 약어 CAGR을 제목으로 사용하지 않는다. 수익률 선택값이 투자 추천·과거 성과가 아닌 계산 가정이라는 짧은 안내를 유지한다.
- 390px, 768px, desktop에서 큰 원화 헤드라인과 목표 입력이 가로 overflow 없이 읽히고 조작돼야 한다.

## 수용 조건

1. 결과 화면은 선택 기간의 최종금액 대신 다음 목표 도달 예상 기간을 핵심 문장 하나로 보여준다.
2. 목표 규칙은 시작 자산 8천만 원과 2억 원 경계를 정확히 처리한다.
3. 2억 원 이상 사용자는 별도 단일 질문 화면에서 목표를 입력하고, 기존 2억 원 이상 사용자도 목표를 잃지 않고 보완할 수 있다.
4. 목표 도달은 현재 명목·실질 모드에서 월 단위로 계산하되 최대 30년까지만 탐색한다.
5. 도달하지 못한 경우 오해 없이 30년 내 미도달을 알린다.
6. 그래프 기간은 사용자의 설정을 유지하며 목표 계산이 자동으로 바꾸지 않는다.
7. Main은 읽기 전용이고 Simulation 외 저장 경계는 변하지 않는다.

## 2026-09-11 확장 — 목표와 가정

- 사용자 요청: 자동 목표·도달 계산을 기본으로 유지하면서 결과 하단에서 목표를 1천만 원 단위로 직접 설정한다.
- `계산 기준`을 `목표와 가정` 패널로 재구성한다. 후속 사용자 피드백에 따라 기본으로 접고 현재 목표·시작 자산을 요약한다. 한 번 펼치면 목표·시작 자산과 금리·물가·비자문 안내를 함께 표시한다. 중첩 disclosure는 제거한다. 명목·실질은 바깥에 두고 항상 보이게 한다. 새 초안 기준금리는 3.0%이고 기존 물가 차이 -0.25%p와 저장된 금리는 유지한다. 목표 입력 아래에도 같은 도달 계산에서 얻은 예상 기간을 `aria-live`로 표시해 상단으로 돌아가지 않아도 변경 결과를 확인할 수 있다.
- 목표는 쉼표를 허용하는 원 입력, `−5천만 / −1천만 / +1천만 / +5천만`, 현재 설정 출처 텍스트 옆의 초기화 아이콘(`기본 목표로`)을 제공한다. 아이콘은 44px 조작 영역·접근 가능한 이름·title을 가지며, 기본 목표 상태에서는 비활성화한다. 직접 입력은 Enter 또는 blur에서 유효한 값만 반영하며 숫자 형식·안전 정수·1천만 단위·시작 자산 초과를 검증한다. 오류는 입력 옆에 남기고 기존 결과·저장값을 유지한다. Escape로 저장된 목표를 복원한다.
- 시작 자산 2억 미만은 기존 기본 목표 계산을 그대로 사용한다. 2억 이상은 기존의 사용자 목표 질문을 유지하며 사용할 자동 목표가 없으므로 기본 목표 복원 버튼을 표시하지 않는다.
- 별도 자동/수동 모드 필드는 추가하지 않는다. `기본 목표`는 현재 금액이 기본 계산값과 같다는 표시다. 시작 자산 수정 시 기존 정책(기본 목표와 같은 값은 새 기본 목표로, 다른 목표는 시작 자산보다 큰 동안 유지)을 보존한다. 사용자 목표에 시작 자산이 도달하면 기존 다음 목표 결정/질문 경로를 사용한다.
- 저장 계약은 Simulation v3 `targetAmountWon`, workspace v5 및 계정 저장 RPC 그대로다. 기존 원 단위 사용자 목표는 방문·focus·blur만으로 반올림하거나 거부하지 않는다. 증감을 누를 때만 다음/이전 1천만 원 경계로 이동한다. 새 직접 수정값에는 1천만 원 단위를 적용한다.
- 최대 30년 월 단위 도달 탐색과 명목·실질 계산은 변경하지 않는다. 목표 변경으로 그래프 기간이나 Main·다른 앱 slice를 수정하지 않는다.
- 390px에서는 금액 입력을 한 열로, 768px·desktop에서는 두 열로 배치한다. 공통 MoneyAdjustments·SegmentedControl, 44px 조작 영역, 키보드 focus·오류 연결·reduced motion을 유지한다.
- 검증: 입력·최소값·안전 정수·기존 원 단위 목표·기본 복원 unit, Simulation 전체 focused unit/E2E, 새로고침 저장·Main 보존 및 세 화면 크기 캡처.

## 2026-09-11 후속 — 결과 화면 위계와 기본 5년

- 새 Simulation 초안은 5년으로 시작한다. 저장된 기간은 자동 변경하지 않으며 목표 도달 계산은 최대 30년을 그대로 탐색한다.
- 상단은 목표 도달 요약으로 유지한다. 그 아래 하나의 자산 변화 패널에서 선택한 기간을 제목으로 명시하고 명목·실질·그래프·기간·수익률·보조 비교를 함께 제공한다.
- 그래프와 조작은 패널 안에서 별도 카드 외곽선 없이 붙이고, 비교값의 글자 크기와 여백을 줄여 보조 위계로 둔다. 납입원금 비율은 백분율 대신 `넣은 돈 대비 N배`로 풀어 쓴다. 계산 값은 같은 비율을 사용한다.
- `목표와 가정`은 그 아래 기본으로 접힌 설정으로 유지한다. 명목·실질은 그래프 제목으로 옮겨 설정을 펼치지 않고 확인·변경할 수 있다.
- 모바일은 그래프의 최소 높이를 조정해 불필요한 상하 여백을 줄인다. 축 글자 크기, tooltip 및 키보드·터치 계약은 유지한다.
