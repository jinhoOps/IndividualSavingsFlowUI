# 포커스 기반 금액 빠른 조정 설계

## 목적

Main 편집 화면의 반복적인 빠른 조정 UI를 현재 편집 대상에만 노출하고, Simulation 시작 자산 입력에는 큰 금액을 빠르게 증감할 수 있는 조작을 제공한다.

## 범위

### Main

- `월 자금 계획 편집`의 각 `MoneyField`는 입력 또는 같은 필드의 빠른 조정 버튼에 포커스가 있을 때만 `.money-field__adjustments`를 표시한다.
- 입력에서 빠른 조정 버튼으로 포커스를 옮기는 동안 버튼이 사라지지 않는다.
- 다른 입력으로 포커스가 이동하면 빠른 조정 버튼도 새 대상 아래에 표시된다.
- 최초 설정 흐름의 `MoneyField`는 기존처럼 빠른 조정 버튼을 항상 표시한다.
- 공용 `MoneyField`에 노출 방식을 명시하는 옵션을 추가하고, Financial Detail 편집기만 포커스 기반 방식을 선택한다.

### Simulation

- `현재 모아둔 투자금` 입력 아래에 `-1000만`, `-100만`, `+100만`, `+1000만` 버튼을 이 순서로 표시한다.
- 각 버튼은 현재 입력값에서 각각 `-10,000,000`, `-1,000,000`, `+1,000,000`, `+10,000,000`원을 적용한다.
- 차감 결과는 0원보다 작아지지 않는다.
- 직접 입력과 빠른 조정은 동일한 정수 원화 값을 갱신한다.
- 버튼은 390px 화면에서 4열 한 줄을 유지하고 각 터치 대상 높이는 최소 44px이다.

## 접근성 및 반응형

- 버튼의 접근 가능한 이름은 화면에 보이는 한글 금액 표기와 같다.
- 키보드 사용자는 Main 입력에서 같은 필드의 빠른 조정 버튼으로 이동할 수 있다.
- 포커스가 빠른 조정 영역 안에 있는 동안 Main 버튼은 계속 표시된다.
- Simulation 버튼은 가로 overflow나 단독 줄바꿈 없이 390px, 768px, desktop에 표시된다.

## 상태 및 데이터 경계

- Main과 Simulation의 저장 schema는 변경하지 않는다.
- Main은 기존 `onChange(valueWon)` 경계를 유지한다.
- Simulation 시작 자산은 기존 onboarding 로컬 상태만 갱신하며, 다음 단계로 이동하기 전에는 저장하지 않는다.

## 검증

- Main 단위 테스트로 기본 상시 노출과 포커스 기반 클래스 계약을 확인한다.
- Main Playwright 테스트로 Financial Detail에서 활성 필드의 버튼만 보이고 입력 간 포커스 이동에 따라 대상이 바뀌는지 확인한다.
- Simulation 단위 테스트로 네 증감값과 0원 하한을 확인한다.
- Simulation Playwright 테스트로 390px에서 네 버튼이 한 줄이며 최소 44px 높이인지 확인한다.
- `npm run check`, 관련 단위 테스트와 관련 Playwright spec을 실행한다.
