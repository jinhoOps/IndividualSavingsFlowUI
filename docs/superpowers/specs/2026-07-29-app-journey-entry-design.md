# 앱 여정 진입점과 레거시 격리 설계

## 목적

Main을 현재 제품의 홈으로 유지하면서 `Main → Simulation → Portfolio` 여정의 진입 흐름을 먼저 검증한다. Simulation, Portfolio, Account Map의 상세 기능은 후속 명세에서 신규 React·TypeScript·Tailwind 앱으로 설계한다.

현재 동명 바닐라 앱은 제품 구현이 아니라 기능과 데이터 계약을 파악하기 위한 임시 레거시 자원이다. 이번 작업은 레거시를 정상 사용자 경로와 신규 런타임에서 명시적으로 격리하지만 물리적으로 삭제하지 않는다.

## 범위

### 포함

- Main을 홈으로 사용하는 공통 앱 런처
- Main의 Simulation 진입 CTA
- 신규 Simulation 및 Portfolio 준비 화면
- 앱 간 최소 `JourneySnapshot` 계약
- 새로고침을 위한 신규 전용 로컬 저장
- 데스크톱과 모바일의 진입 흐름
- 레거시 격리를 입증하는 정적 검사와 사용자 흐름 테스트

### 제외

- Simulation, Portfolio, Account Map의 상세 계산·편집·저장 기능
- 기존 동명 레거시 앱의 기능 재사용
- 레거시 파일의 물리 삭제
- 금융기관 또는 서버 연동
- Main 전체 데이터의 앱 간 공유

## 제품 상태

- **Main:** 현재 사용 가능한 제품 기준선
- **Simulation:** 신규 개발 예정, 이번 범위에서는 준비 화면
- **Portfolio:** 신규 개발 예정, 이번 범위에서는 준비 화면
- **Account Map:** 신규 개발 예정, 이번 범위에서는 런처의 준비 중 목적지

기존 `apps/simulation`, `apps/portfolio`, `apps/account-map` 구현의 완성도는 위 제품 상태 판단에 사용하지 않는다.

## 정보 구조

Main이 기본 진입점이다. 별도 허브 홈을 만들지 않는다.

Main 상단의 공통 앱 런처는 네 목적지를 항상 보여준다.

- Main: `사용 중`
- Simulation: `준비 중`
- Portfolio: `준비 중`
- Account Map: `준비 중`

데스크톱에서는 현재 위치와 목적지 상태를 한눈에 읽을 수 있는 런처를 사용한다. 모바일에서는 동일 정보를 축약 메뉴로 제공한다. 상태 표시는 색상만 사용하지 않고 텍스트와 현재 위치 표시를 함께 제공한다.

## 핵심 사용자 흐름

### 최초 사용자

1. 사용자가 Main에 진입한다.
2. `Simulation으로 이어가기` CTA는 보이지만 아직 활성화되지 않는다.
3. CTA 주변 안내는 Main 계획 입력이 선행 조건임을 설명한다.
4. 사용자가 Main 빠른 설정을 완료하고 유효한 계획을 적용한다.
5. CTA가 활성화된다.

### Main 정보가 있는 사용자

1. Main 대시보드에서 활성화된 `Simulation으로 이어가기`를 선택한다.
2. Main이 최신 `JourneySnapshot`을 생성하고 신규 전용 저장소에 기록한다.
3. 신규 Simulation 준비 화면으로 이동한다.
4. 화면은 연결 성공, 월 투자 가능액, Main 갱신 시각을 보여준다.
5. 사용자가 `Portfolio로 이어가기`를 선택한다.
6. 동일 계약을 유지한 채 신규 Portfolio 준비 화면으로 이동한다.
7. Portfolio 준비 화면은 전달된 요약과 연결 성공을 보여준다.

적자 또는 월 투자 가능액 0원은 연결 실패가 아니다. 이동을 허용하고 현재 상태를 설명한다.

## `JourneySnapshot` 계약

계약은 앱 간 결합을 최소화하기 위한 읽기 전용 요약이다.

```ts
interface JourneySnapshot {
  version: 1;
  sourceApp: 'main' | 'simulation';
  sourceView: 'dashboard' | 'simulation-readiness';
  destinationApp: 'simulation' | 'portfolio';
  monthlyInvestableAmountWon: number;
  mainUpdatedAt: number;
  createdAt: number;
}
```

규칙:

- 금액 단위는 원이다.
- 모든 시각은 Unix epoch millisecond다.
- `monthlyInvestableAmountWon`은 0 또는 음수일 수 있지만 유한한 정수여야 한다.
- 스냅샷에는 계좌, 상세 소비, 저축 상품, 자산 종목 또는 사용자 식별 정보를 넣지 않는다.
- Main 도메인 객체와 레거시 저장 객체를 그대로 직렬화하지 않는다.
- 소비자는 런타임에서 모든 필드와 계약 버전을 검증한다.
- 알 수 없는 버전이나 손상된 값은 부분 사용하지 않고 전체를 거부한다.

## 저장과 수명

- `JourneySnapshot`은 기존 앱 저장 키와 겹치지 않는 신규 전용 키에 저장한다.
- 준비 화면 새로고침 후에도 마지막 유효 스냅샷을 복구한다.
- 준비 화면은 스냅샷을 읽을 뿐 Main 데이터를 수정하지 않는다.
- 사용자가 Main에서 다시 진입하면 최신 값으로 스냅샷을 교체한다.
- 준비 화면은 Main 갱신 시각을 표시하고 `Main에서 최신 정보 가져오기` 경로를 제공한다.

## 준비 화면 책임

Simulation 및 Portfolio 준비 화면은 다음만 담당한다.

- 목적지와 `준비 중` 상태 안내
- 앱 간 연결 성공 여부 표시
- 전달된 월 투자 가능액과 Main 갱신 시각 표시
- 이전 또는 다음 목적지로 이동
- 스냅샷 오류 시 복구 경로 안내

준비 화면은 금융 계산, 계획 편집, 독립 저장, 레거시 데이터 변환을 수행하지 않는다.

## 오류 처리

- **스냅샷 없음:** Main에서 계획을 먼저 완성하도록 안내한다.
- **계약 버전 불일치:** 데이터를 무시하고 Main에서 다시 시작하도록 안내한다.
- **손상 또는 비정상 값:** 데이터를 무시하고 오류 세부정보 대신 안전한 복구 행동을 제공한다.
- **0원 또는 적자:** 정상 연결로 표시하고 금액 상태를 명확히 설명한다.
- **오래된 값:** 자동 실패 처리하지 않는다. 갱신 시각과 Main 재진입 행동을 제공한다.
- **저장 실패:** 현재 탐색을 중단하고 Main 데이터는 변경하지 않는다.

## 명시적 레거시 격리

격리는 파일 보존과 사용자 경로 분리를 동시에 만족해야 한다.

1. `/apps/simulation`, `/apps/portfolio`, `/apps/account-map`의 제품 진입점은 신규 준비 화면 또는 신규 앱 엔트리가 소유한다.
2. 공통 런처와 Main CTA는 기존 바닐라 HTML 또는 JavaScript로 연결하지 않는다.
3. 신규 엔트리, 계약, 화면은 `src/` 아래에 존재하며 `apps/*` 레거시 모듈을 import하지 않는다.
4. 신규 코드에서 `CompatibilityBridge`, 레거시 전역 객체, 레거시 저장 키를 읽거나 호출하지 않는다.
5. Vite의 정상 빌드 입력과 PWA 내비게이션 대상은 신규 엔트리만 가리킨다.
6. 기존 레거시 파일은 기능 조사 전용으로 남기되 제품 런타임 청크에 포함하지 않는다.
7. E2E는 모든 런처와 CTA가 신규 준비 화면으로 도착함을 확인한다.
8. 정적 검색은 신규 진입점에서 레거시 runtime import, route, 전역 객체 및 저장 키 참조가 없음을 확인한다.

위 조건 중 하나라도 충족하지 않으면 격리가 확보된 것으로 보지 않는다.

## 접근성 및 반응형

- CTA의 비활성 상태와 이유를 보이는 텍스트로 설명한다.
- 준비 중 상태를 색상만으로 전달하지 않는다.
- 현재 앱은 `aria-current` 등 의미 있는 상태로 표시한다.
- 키보드로 런처, CTA, 이전·다음 이동을 사용할 수 있다.
- 모바일 CTA는 전체 너비와 최소 44px 터치 영역을 확보한다.
- 390px 화면에서 목적지 이름, 상태, 금액이 겹치거나 가로로 넘치지 않는다.
- 사용자가 선호하는 reduced motion을 존중하며 연결 상태 표현에 필수 애니메이션을 사용하지 않는다.

## 테스트 전략

### 단위 및 컴포넌트

- 유효한 `JourneySnapshot` 생성과 직렬화
- 누락 필드, 잘못된 타입, 비정상 금액, 미지원 버전 거부
- Main 정보가 없을 때 CTA 표시와 비활성 안내
- Main 정보가 유효할 때 CTA 활성화
- 런처의 현재 앱과 준비 중 상태
- 준비 화면의 정상, 없음, 손상, 0원, 적자 상태

### E2E

- 최초 사용자에게 Main 입력이 선행됨
- 적용된 Main 계획에서 Simulation 준비 화면으로 이동
- Simulation 준비 화면에서 Portfolio 준비 화면으로 이동
- 준비 화면 새로고침 후 유효 스냅샷 복구
- 손상된 저장 값 거부 후 Main 복구 경로 제공
- 데스크톱과 390px 모바일에서 런처 및 전체 흐름 사용
- 모든 제품 진입 경로가 기존 레거시 UI가 아닌 신규 준비 화면에 도착

### 격리 검사

- 신규 엔트리의 `apps/*` import 부재
- 신규 코드의 compatibility 전역 및 레거시 저장 키 참조 부재
- Vite 입력과 PWA 라우트가 신규 엔트리를 가리킴
- 빌드 결과에 레거시 앱 엔트리 청크가 포함되지 않음

## 후속 신규 앱 명세의 필수 항목

Simulation, Portfolio, Account Map의 각 상세 기능 명세는 해당 레거시 제거 계획을 함께 승인받아야 한다.

각 명세는 다음을 포함한다.

1. 레거시 기능과 사용자 관찰 동작 목록
2. 신규 앱에 보존, 재설계 또는 폐기할 항목과 근거
3. 이관할 데이터 계약과 저장 데이터 호환 정책
4. 신규 앱이 소유할 route, runtime, selector, storage 및 test 경계
5. 레거시 import, route, selector, storage key, 전역 객체, compatibility path와 test fixture 제거 목록
6. 구버전 데이터 검증 및 사용자 데이터 손실 방지 절차
7. 신규 앱 회귀와 레거시 참조 부재를 입증하는 명령
8. 삭제 가능한 파일 목록과 삭제 불가 항목의 근거

상세 요구사항, 호환 정책, 회귀 증거가 준비되기 전에는 레거시 파일을 삭제하지 않는다. 조건이 충족된 앱은 같은 구현 계획 안에서 관련 레거시 제거까지 완료한다.

## 완료 기준

- Main이 홈이며 네 목적지의 상태를 보여주는 런처가 존재한다.
- Main 입력 전후의 Simulation CTA 상태가 명확하다.
- `Main → Simulation 준비 화면 → Portfolio 준비 화면` 흐름이 실제 라우트에서 동작한다.
- 최소 `JourneySnapshot`만 전달되고 새로고침 후 복구된다.
- 0원과 적자도 유효한 연결 상태로 처리된다.
- 기존 동명 앱이 정상 사용자 경로, 신규 import graph, 빌드 엔트리와 PWA 목적지에서 격리된다.
- 격리 조건이 자동 테스트와 정적 검사로 입증된다.
- 레거시 파일은 조사 자원으로 보존되며 상세 앱 명세 전에는 삭제되지 않는다.
