# 메인 앱 시각 체계 통일 설계

## 목적

초기 설정 화면과 이후 추가된 요약·편집 요소의 모양을 하나의 시각 체계로 통일한다. 기능과 저장 데이터는 유지하면서, 화면마다 달라진 버튼·입력창·카드·게이지의 규칙을 공통화한다.

## 범위

- 빠른 설정 전체 단계
- 설정 완료 후 메인 대시보드
- 금액 편집 화면과 저장·취소 영역
- 금액 입력 및 증감 버튼
- 수입 대비 흐름 게이지와 자금 구성 바
- 오류, 저장 중, 키보드 포커스, 모바일 터치 상태

저장 모델, 복구 정책, 백업 형식, GitHub Pages 경로와 배포 방식은 변경하지 않는다.

## 기술 경계

새 메인 앱의 실행 소스는 `src/main/**/*.ts`와 `src/main/**/*.tsx`만 사용하며, React·Vite·TypeScript·Tailwind CSS 조합을 유지한다. 브라우저 배포 결과가 JavaScript로 변환되는 것은 정상적인 빌드 결과다.

`apps/main/**/*.js`에 남은 예전 메인 코드와 다른 앱·공용 영역의 JavaScript는 이번 시각 체계 전환에서 새로 참조하지 않는다. 일부 다른 앱이 예전 메인 모듈을 사용하고 있으므로 지금 삭제하거나 일괄 변환하지 않는다. 다른 앱 연결 설계에서 의존성을 공용 TypeScript 경계로 분리한 뒤 레거시 JavaScript 제거와 전환 범위를 결정한다.

## 시각 원칙

1. 정보보다 장식이 앞서지 않는다.
2. 같은 역할은 모든 화면에서 같은 모양과 상태를 사용한다.
3. 주요 행동만 강하게 보이고 나머지는 평평하고 조용하게 표현한다.
4. 금액 흐름은 한눈에 읽히게 하고 상세 비율은 요청할 때만 보여준다.
5. 포인터, 키보드, 터치에서 같은 정보를 얻을 수 있어야 한다.

## 디자인 토큰

색상, 간격, 모서리 반경, 그림자, 테두리, 포커스 링, 컨트롤 높이를 공통 토큰으로 정의한다. 기존 브랜드 색상과 한글 글꼴은 유지하되 컴포넌트 내부의 임의 Tailwind 값은 토큰 또는 공통 변형으로 모은다.

카드에는 한 종류의 기본 표면을 사용한다. 강조가 필요한 경우 색을 새로 만들지 않고 테두리나 배경 명도만 조절한다. 그림자는 화면 계층을 구분할 때만 사용한다.

## 공통 컴포넌트

### Button

- `primary`: 다음, 적용, 저장처럼 화면을 진행하는 행동
- `secondary`: 이전, 취소처럼 보조적인 행동
- `quiet`: 금액 증감과 초기화처럼 반복해서 쓰는 작은 행동
- 모든 변형은 높이, 반경, 비활성화, 포커스 상태를 공유한다.
- `-10만`, `+10만`, `+50만`, `초기화`는 같은 크기의 평평한 `quiet` 버튼으로 표시한다. 초기화는 색 대비만 한 단계 낮춘다.
- 좁은 화면에서는 자연스럽게 줄바꿈하며 최소 터치 영역을 보장한다.

### Card

- 설정, 요약, 편집 영역에 동일한 표면·테두리·반경 규칙을 적용한다.
- 중첩 카드 사용을 최소화해 화면이 여러 겹의 상자로 보이지 않게 한다.

### MoneyField

- 라벨, 입력창, `원` 단위, 증감 버튼, 오류 문구의 간격을 고정한다.
- 입력 중 쉼표와 커서 보존 등 기존 동작은 유지한다.
- 기본, 포커스, 오류, 비활성화 상태를 공통 규칙으로 표현한다.

### FlowBar와 Tooltip

- 입력 단계 상단의 정보 게이지는 높이 약 6px의 납작한 바로 표현한다.
- 상시 노출되던 설명, 금액, 범례, 비율 문구는 제거한다.
- hover와 키보드 focus에서는 현재 비율만 담은 툴팁을 포인터 또는 활성 지점 가까이에 표시한다.
- tap에서는 누른 위치 가까이에 같은 툴팁을 표시하고, 바깥을 누르거나 다른 요소로 이동하면 닫는다.
- 툴팁 문구는 `56.3%`처럼 비율만 표시한다.
- 키보드 사용자가 전체 바에 접근할 수 있도록 바 자체가 포커스 대상이 된다.
- 0%에서도 전체 바가 상호작용 영역으로 남는다.

### AllocationBar

- 자금 구성의 여러 구간은 기존 의미와 계산을 유지한다.
- FlowBar와 같은 높이, 모서리, 툴팁 동작을 사용한다.
- 화면에서 항상 필요한 항목명과 금액만 남기고 비율은 툴팁에서 제공한다.
- 0% 또는 매우 작은 구간도 키보드와 터치에서 정보를 확인할 수 있는 별도 접근 경로를 유지한다.

## 화면 적용

빠른 설정과 대시보드는 동일한 카드, 제목 계층, 입력창, 버튼을 사용한다. 설정 진행률과 자금 흐름 바는 용도가 다르므로 색상 의미는 구분하되 두께와 모서리 규칙은 공유한다.

모바일 편집 패널은 기존 바텀시트 동작을 유지하면서 내부 컴포넌트만 공통 체계로 교체한다. 데스크톱 편집 영역도 같은 컴포넌트를 사용해 화면 크기에 따라 모양이 달라지지 않게 한다.

## 상태와 접근성

- 모든 상호작용 요소에 명확한 `focus-visible` 상태를 제공한다.
- 오류는 색상뿐 아니라 문구와 `aria-invalid`로 전달한다.
- 저장 중에는 중복 행동을 막고 기존 포커스 흐름을 유지한다.
- 툴팁은 포인터에만 의존하지 않으며 focus와 tap에서도 동일한 비율을 제공한다.
- 동작 감소 설정에서는 불필요한 전환 효과를 제거한다.

## 테스트

- 공통 버튼 변형과 비활성화 상태
- MoneyField의 쉼표 입력, 커서 보존, 증감, 초기화, 오류 상태
- FlowBar의 hover, focus, tap 툴팁과 0% 상호작용 영역
- AllocationBar의 0% 및 작은 구간 접근성
- 설정과 대시보드의 공통 컴포넌트 사용
- 모바일 편집 패널의 포커스 이동과 터치 툴팁
- 기존 저장, 복구, 백업, GitHub Pages 경로 회귀

## es-toolkit 결정

현재 메인 앱에는 `debounce`, `groupBy`, `uniq`, 복잡한 객체 변환처럼 외부 유틸이 반복해서 해결할 문제가 없다. 단순 데이터 복사와 배열 순회는 현재 TypeScript와 표준 JavaScript로 충분하므로 이번 전환에는 `es-toolkit`을 도입하지 않는다.

다른 앱 연결 설계에서 공통 변환, 컬렉션 처리, 실행 제어 유틸이 여러 앱에 반복되면 다음 기준으로 다시 검토한다.

- 동일하거나 유사한 유틸 구현이 세 곳 이상 반복되는가
- 표준 API보다 검증된 외부 구현이 오류 가능성을 실질적으로 낮추는가
- 필요한 함수만 가져왔을 때 번들 증가가 허용 범위인가
- 연결 앱 사이의 공통 타입과 동작을 더 명확하게 만드는가

조건을 충족할 때만 독립적인 기술 결정으로 도입한다.

## 완료 기준

- 설정, 대시보드, 편집 화면의 공통 요소가 같은 시각 규칙을 사용한다.
- 정보 게이지가 납작한 바로 보이며 비율은 hover·focus·tap 툴팁에서만 표시된다.
- 초기와 후속 컴포넌트 사이의 버튼·입력·카드 모양 차이가 제거된다.
- 기존 기능, 데이터, 배포 경로에 회귀가 없다.
