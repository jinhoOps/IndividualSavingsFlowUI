# Portfolio Summary-First UX Design

## 1. 목적

Portfolio의 첫 화면을 "이번 달 투자금이 어디에 몇 % 배분되는가"에 즉시 답하는 요약 화면으로 바꾼다. 큰 도넛과 중복 표를 제거하고, 항목 이름·비율·비례 막대만으로 배분을 읽게 한다. 원화 금액은 기본적으로 숨기며 사용자가 관리 메뉴에서 전체 표시를 켤 수 있다.

이 변경은 Portfolio의 단일 적용 배분·편집 초안, 최신 Main 투자금 읽기 전용, Main 비수정 계약을 유지한다. 시세, 수익률, 위험 점수, 계좌와 매수 기능은 추가하지 않는다.

## 2. 사용자 목표

사용자는 Portfolio 진입 직후 다음 질문에 답을 얻어야 한다.

1. 가장 큰 배분 대상은 무엇이며 몇 %인가?
2. 전체 중 안정 비중은 몇 %인가?
3. 나머지 투자 대상은 각각 몇 %인가?

금액이 필요할 때만 한 번의 설정 변경으로 총액과 모든 항목 금액을 함께 볼 수 있어야 한다.

## 3. 승인된 시각 방향

- ISF Pearl canvas, Gowun 계열 서체, AppShell launcher와 기존 ISF 색상 문법을 유지한다.
- 결과는 하나의 평면적인 grouped surface 안에 비율 행을 배치한다.
- 각 행은 색상 표식, 투자 대상 이름, 비례 막대와 큰 비율을 제공한다.
- 별도의 도넛과 중복 데이터 표는 제거한다.
- 항목별 카드, 자산군 그림 아이콘, 행 chevron, 불필요한 badge를 추가하지 않는다.
- 모바일 390px에서 네 개 항목의 핵심 정보가 과도한 스크롤 없이 읽혀야 한다.
- 데스크톱에서도 도넛을 다시 추가하지 않고 같은 정보 문법을 넓은 폭에 맞게 정돈한다.

## 4. 결과 화면 정보 구조

### 4.1 금액 보기 OFF — 기본값

- eyebrow: `이번 달 투자금`
- 핵심 요약: `안정 50%` 형식
- 보조 문구: 가장 큰 항목을 설명하는 `{이름}에 {비율}%를 배분해요`
- 항목 행: 이름, 비율, 비례 막대
- 원화 총액과 항목별 원화 금액은 렌더링하지 않는다.

가장 큰 항목은 비율로 결정한다. 동률이면 현재 보기 순서에서 먼저 오는 항목을 사용한다. 현금도 동일한 후보지만 별도 투자 대상이 같은 비율이면 투자 대상을 먼저 사용한다.

### 4.2 금액 보기 ON

- 핵심 요약은 `이번 달 투자금 800,000원` 형식으로 전환한다.
- 안정 비중은 별도 짧은 보조 정보로 유지한다.
- 각 행은 비율을 계속 주값으로 유지하면서 원화 금액을 보조값으로 추가한다.
- 보조 문구는 가장 큰 항목의 이름·비율을 유지하고 해당 항목 원화 금액을 함께 표시할 수 있다.

금액 보기 변경은 일부 행이 아니라 화면 전체에 동시에 적용한다.

### 4.3 편집 진입과 저장 상태

- 큰 `배분 수정` CTA와 결과 화면의 상시 `저장됨` 문구를 제거한다.
- 핵심 요약 옆에 연필 아이콘 버튼 하나를 둔다.
- 버튼의 접근 가능한 이름은 `배분 수정`이며 시각 크기와 무관하게 최소 44px touch target을 제공한다.
- 저장 성공은 결과 화면에 상시 노출하지 않는다.
- 저장 실패와 초안 정리 실패는 기존처럼 명시적인 alert로 노출하고 복구 행동을 제공한다.

## 5. 보기 설정과 관리 메뉴

Portfolio 톱니 관리 메뉴에 `보기 설정`을 추가한다.

- `금액 보기`: on/off checkbox 또는 switch, 기본 off
- `정렬`: `비율순` 또는 `입력순` 단일 선택, 기본 비율순
- 기존 `투자 배분 처음부터 다시`는 구분선 뒤에 유지한다.
- 앱 아이콘 안내는 기존 공통 관리 메뉴 계약을 유지한다.

설정은 Portfolio 전용 UI preference다. 적용 배분 schema와 분리된 새 localStorage record로 저장한다. 저장 불가 시 현재 세션에서는 변경을 반영하되 다음 진입에서 기본값으로 돌아가며, 배분 저장 실패로 오인시키지 않는다.

`비율순`은 비율 내림차순이며 동률은 입력 순서를 사용한다. `입력순`은 저장된 `order`를 사용한다. 정렬은 결과 표시만 바꾸고 저장된 항목 순서와 배분 계산은 변경하지 않는다.

## 6. 성장·안정 분류

### 6.1 저장 모델

각 `PortfolioItem`은 다음 상태를 소유한다.

- `classification`: `growth | stable`
- `classificationOrigin`: `automatic | user`

UI 표기는 `성장`, `안정`만 사용한다. `성장자산`, `안정자산`처럼 `자산`을 반복하지 않는다.

현금은 item이 아니며 항상 안정으로 계산한다.

### 6.2 자동 추천

새 투자 대상은 이름을 정규화한 뒤 다음 규칙으로 초기 분류한다.

- 금현물·금·골드·gold 계열 키워드: 안정 추천
- 채권·국채·회사채·bond 계열 키워드: 안정 추천
- ETF라는 단어만으로 안정 추천하지 않는다.
- ETF 이름에 위 금 또는 채권 계열 키워드가 함께 있을 때만 안정 추천한다.
- 그 밖의 이름과 빈 이름은 성장 추천

`금`은 정규화된 독립 단어 또는 명확한 상품 토큰일 때만 일치시킨다. `금융`, `예금`처럼 다른 단어에 포함된 글자는 금 추천으로 처리하지 않는다.

### 6.3 사용자 지정 우선

- 사용자는 편집 화면에서 각 항목을 `성장 / 안정`으로 언제든 바꿀 수 있다.
- 사용자가 선택하면 `classificationOrigin`은 `user`가 된다.
- `user` 상태에서는 이름이 바뀌어도 자동 추천이 분류를 덮어쓰지 않는다.
- `automatic` 상태에서는 이름 변경 시 추천을 다시 계산한다.
- 사용자가 `자동 추천 사용`을 명시적으로 선택한 경우에만 `automatic`으로 돌아간다.

### 6.4 안정 비중

안정 비중은 다음 합계다.

```text
stable item shareUnits 합계 + cashShareUnits
```

화면 표시에서는 기존 percentage formatting과 반올림 계약을 사용한다. 합계 계산은 표시 문자열이 아니라 정수 `shareUnits`로 수행한다.

## 7. v2 저장 시작과 기존 데이터 경계

Portfolio plan과 draft schema를 v2로 올린다.

- v1 Portfolio plan과 draft는 현재 제품 데이터로 이관하지 않으며 읽거나 삭제하지 않는다.
- v2 저장값이 없으면 최신 Main 투자금을 기준으로 현금 100%인 새 v2 draft를 시작한다.
- v2 저장값만 strict validation하며 잘못된 v2 값은 기존 격리 규칙을 따른다.
- 현금은 schema와 무관하게 안정으로 계산한다.
- 저장 실패 격리와 Main read-only 계약을 유지한다.

보기 설정은 배분 schema와 별도다. 설정 record가 없거나 잘못됐으면 `금액 숨김 + 비율순`을 사용한다.

## 8. 편집 화면

- 입력 방식 `금액 / 비율`은 현재 편집 기능으로 유지한다.
- 각 항목에는 이름, 배분 입력과 `성장 / 안정` 선택을 한 묶음으로 제공한다.
- 자동 추천 상태는 짧은 보조 문구로 설명하되 모든 행에 불필요한 badge를 반복하지 않는다.
- 사용자가 분류를 직접 선택하면 해당 항목에만 사용자 지정 상태와 `자동 추천 사용` 행동을 제공한다.
- 모바일은 한 항목을 세로로 묶되 이름·배분 결과·삭제 문구의 반복을 줄인다.
- 데스크톱은 이름, 분류, 입력값과 결과를 한 행에 정렬한다.
- 현금 section은 `안정`임을 읽을 수 있게 표시하되 변경 control을 제공하지 않는다.

새 항목은 빈 이름 상태에서 성장 추천으로 시작한다. 이름이 입력되면 automatic 규칙으로 분류를 갱신한다.

## 9. 적용 확인

기존 확인 dialog의 핵심 계약을 유지하면서 읽기 순서를 정돈한다.

- 투자 대상 수
- 안정 비중
- 현금 비중
- 금액 보기 on일 때만 총 투자금

dialog의 적용/취소, focus trap, 초기 focus, Escape와 trigger focus 복귀 계약은 유지한다. 결과 뒤에 보이는 고정 apply bar가 dialog 행동보다 시각적으로 강해지지 않도록 backdrop과 z-index를 유지한다.

## 10. 상태와 오류 처리

- Main 투자금 0원 gate, stale Main, 저장소 unavailable과 corrupt draft 격리를 유지한다.
- 분류 자동 추천은 순수 함수이며 실패 상태를 만들지 않는다.
- 잘못된 `classification` 또는 `classificationOrigin`을 가진 v2 저장값은 기존 validation 격리 규칙을 따른다.
- 보기 설정 저장 실패는 배분 plan/draft 저장 상태와 분리한다.
- 항목 추가·이름 변경·분류 변경은 현재 초안 저장 흐름을 사용하며 적용 전 Main이나 applied plan에 write하지 않는다.

## 11. 접근성

- 결과의 막대는 색상만으로 의미를 전달하지 않고 이름과 숫자 비율을 함께 제공한다.
- 비례 막대는 장식 요소로 처리하고 읽기 순서는 이름 → 비율 → 선택적 금액으로 유지한다.
- 연필 아이콘 버튼은 `배분 수정` accessible name과 visible focus를 제공한다.
- 보기 설정은 switch/checkbox와 radio semantics를 사용하고 현재 값을 접근 가능한 이름에서 확인할 수 있게 한다.
- `성장 / 안정` control은 fieldset·legend 또는 동등한 group semantics를 사용한다.
- 자동 추천과 사용자 지정 변경은 screen reader가 인지할 수 있는 상태 문구를 제공한다.
- 모든 interactive target은 44px 이상이며 390px, 768px와 desktop에서 horizontal overflow가 없어야 한다.

## 12. 테스트와 인수 조건

### Domain·storage

- 안정 키워드와 false-positive 경계(`금` 대 `금융`, ETF 단독 대 금·채권 ETF)
- automatic 이름 변경 재추천과 user override 보존
- 안정 비중의 item + cash 합계
- v1 plan/draft를 읽지 않고 최신 Main 투자금으로 새 v2 draft 시작
- 잘못된 v2 분류 격리
- 별도 보기 설정의 기본값·저장·invalid fallback

### UI

- 금액 off에서 원화 총액·행 금액이 없고 안정 비중·가장 큰 항목 문구가 보임
- 금액 on에서 총액과 모든 행 금액이 함께 보임
- 비율순·입력순 전환이 표시만 바꾸고 저장 order를 바꾸지 않음
- 결과 화면에 도넛, 중복 표, `저장됨`, 큰 수정 CTA가 없음
- 연필 아이콘으로 편집 진입 및 focus 가능
- edit에서 성장·안정 변경, 자동 추천 복귀와 현금 안정 읽기 가능
- management menu에서 보기 설정과 reset 모두 keyboard·touch로 동작
- 저장 오류는 성공 상태 제거와 무관하게 계속 노출됨

### Responsive·visual

- 390px에서 상단 요약과 최소 네 행이 명확하며 overlay·fixed bar가 content를 가리지 않음
- 768px과 desktop에서 과도한 빈 공간·거대 시각화 없이 content 폭 유지
- 200% zoom과 긴 한글 이름에서 비율·금액·control overflow 없음
- reduced motion에서 의미 손실 없음

## 13. 범위 제외

- 시장 위험도 계산 또는 투자 권고
- 수익률, 가격, 거래와 계좌 연결
- 분류별 목표 비중 또는 경고
- 복수 Portfolio
- Main write-back
- 사용자 정의 분류 추가
