# Simulation 결과 중심 경험 재설계

> **부분 대체:** 상시 `저장됨` indicator 계약은 [Anime.js 공통 모션 시스템 설계](2026-08-12-animejs-motion-system-design.md)가 대체한다. 저장 실패·복구와 나머지 Simulation 계약은 유지한다.

## 문서 상태

- 승인일: 2026-08-03
- 범위: Simulation 최초 설정, 결과 화면, 조작, 그래프 탐색, Main 동기화와 저장 피드백
- 선행 문서: [Simulation 복리 성장 시각화 설계](2026-07-30-simulation-compound-growth-design.md)
- 우선순위: 이 문서는 선행 문서의 UX와 동기화 결정을 대체한다. 계산식, Main read-only 경계, Simulation 전용 저장과 제외 범위는 명시적으로 변경한 항목 외에는 유지한다.

## 문제

현재 Simulation은 필요한 기능을 카드로 나열하지만 Main의 결과 중심 정보 위계와 flat editorial 미감을 계승하지 못한다. 결과, 그래프, 입력과 가정이 각각 독립된 표면처럼 보이며 사용자가 화면 구조를 먼저 이해해야 조작할 수 있다.

재설계는 다음 문제를 해결한다.

- 핵심 결과보다 설명과 조작이 먼저 보인다.
- 기간과 기대수익률에 중복 조작이 많다.
- 같은 입력과 결과를 여러 카드와 문구가 반복한다.
- 기본 그래프는 단순하지만 탐색 시 제공하는 정보도 빈약하다.
- 최초 사용자와 재방문 사용자에게 같은 밀도의 화면을 제공한다.
- Main 변경 후 최신 값을 반영하려면 사용자가 별도 재시작을 이해해야 한다.
- 큰 금액이 한국식 단위로 일관되게 읽히지 않는다.

## 목표

1. 최초 사용자는 제품 지식 없이 화면을 따라 Simulation을 완료한다.
2. 재방문 사용자는 설명 단계를 반복하지 않고 결과 화면에 바로 도착한다.
3. 결과 화면은 문장 하나, 조건 한 줄, 큰 그래프와 비교값 두 개로 핵심을 전달한다.
4. 기본 그래프는 절제하고 pointer, touch와 keyboard 탐색 시 연도별 정보를 풍부하게 제공한다.
5. 최신 Main 월 저축·투자를 별도 행동 없이 자동 반영한다.
6. Main의 ISF Pearl, flat editorial panel, 서체와 시각 위계를 Simulation에 일관되게 적용한다.

## 비목표

- 복리 계산식, 저축 기준선 또는 명목·실질 계산 정책 변경
- Main 데이터 수정 또는 Simulation에서 Main으로 write-back
- 여러 Simulation 저장, 이름, 목록과 비교
- 목표 금액 도달 시점, 종목, 백테스트, 세금, 수수료, 환율 또는 MDD
- 5%, 9%, 13%를 상품 추천이나 예상 성과로 설명하는 기능
- 결과 화면의 카드 수를 늘리는 상세 분석 dashboard

## 경험 원칙

### 결과 우선

핵심 결과는 문장 하나에 집중한다. 같은 금액, 기간 또는 의미를 제목, 카드와 보조 문장에서 반복하지 않는다.

### 행동 유도

사용자가 Simulation 구조나 금융 용어를 미리 알 필요가 없어야 한다. 각 단계는 한 가지 결정을 요구하고 다음 행동 하나를 강조한다.

### 필요한 정보만 노출

조작에 필요한 label과 상태는 유지하되 긴 설명, 중복 합계, 항상 열린 고급 설정과 독립 카드 경계를 제거한다.

### 점진적 공개

최초 설정은 쉬운 질문으로 시작한다. 복리, 명목, 기준금리, 물가상승률과 재투자 가정은 결과 화면의 `계산 기준`에서 필요할 때 공개한다.

## 전체 사용자 흐름

### Main 계획이 없는 진입

유효한 Main 월 저축액과 투자액 합계가 0원이거나 Main 계획이 없으면 Simulation 설정 화면을 만들지 않는다.

- `Main에서 월 저축·투자 금액을 먼저 정해주세요.`를 표시한다.
- Main 설정으로 이동하는 단일 primary action을 제공한다.
- 기존 Main 데이터는 변경하지 않는다.

### 최초 진입

Simulation draft가 없는 사용자는 두 단계 안내형 설정을 진행한다.

#### 1단계: 시작 원금

질문은 하나만 표시한다.

> 지금 모아둔 투자금이 있나요?

- `있어요`
- `없어요`
- `있어요`를 선택한 뒤에만 시작 원금 입력을 표시한다.
- `없어요`는 시작 원금 0원을 적용한다.
- 현재 선택에서 가능한 다음 행동 하나만 primary action으로 강조한다.

#### 2단계: 기간과 기대수익률

다음 자연어 질문으로 시작한다.

> 얼마나 오래, 어느 정도 수익을 기대할까요?

표시 순서:

1. 기간
2. 기대수익률
3. 실시간 핵심 문장
4. 작은 그래프 미리보기
5. `결과 보기`

기본값은 기간 20년, 연 기대수익률 9%다. 기본값은 추천 성과가 아니라 계산 시작값이며 프리셋도 상품이나 과거 성과를 뜻하지 않는다는 짧은 설명을 둔다.

조작할 때 핵심 문장과 작은 그래프를 즉시 갱신한다. 사용자는 `결과 보기` 전에 조건의 영향을 확인할 수 있다.

### 재방문

완료된 draft가 있으면 안내형 설정을 반복하지 않고 결과 화면을 바로 표시한다.

- 저장된 시작 원금, 기간, 기대수익률, 기준금리, 물가 차이와 금액 기준을 유지한다.
- 진입 시 최신 Main의 월 저축·투자를 자동 반영한다.
- 갱신된 조건으로 한 번 계산하고 draft를 자동 저장한다.
- 별도 `최신 Main 가져오기` 또는 재시작 행동을 요구하지 않는다.

### 다시 설정

눈에 띄는 본문 버튼을 두지 않는다. 앱 메뉴 안에 `시뮬레이션 다시 설정`을 제공한다.

- 실행 전 Simulation 설정이 초기화됨을 확인한다.
- Simulation draft만 삭제한다.
- 최신 Main 값은 유지한다.
- 최초 설정 1단계로 이동한다.
- Main 데이터는 변경하지 않는다.

## 결과 화면

### 정보 위계

첫 화면은 다음 순서만 유지한다.

1. 핵심 문장
2. 조건 한 줄
3. 전체 폭 성장 그래프
4. 비교값 두 개
5. 기간과 기대수익률 조작
6. `명목 · 실질` 토글과 접힌 `계산 기준`

### 핵심 문장

결과 화면에서 문장형 정보는 하나에 집중한다.

> 이대로 20년 유지하면 4억 8,241만 원이 됩니다!

- 기간과 최종 현재 계획 금액을 현재 조건에서 만든다.
- `0년`은 `현재`로 표현하고 `현재 시작 자산은 3,000만 원입니다!` 형식을 사용한다.
- 같은 결과를 별도 화면 제목이나 요약 카드에서 반복하지 않는다.
- 핵심 숫자와 문장은 Gowun Batang 계층을 사용한다.

### 조건 한 줄

`이대로`의 의미를 한 줄로 설명한다.

> 월 저축 80만 원 · 투자 120만 원 · 연 9%

- 월 납입 합계를 별도로 반복하지 않는다.
- 각 값은 Main source와 Simulation 기대수익률에서 만든다.
- 값이 바뀌면 핵심 문장, 조건 한 줄과 그래프를 같은 render에서 갱신한다.

### 비교값

그래프 다음에 두 값만 나란히 표시한다.

- `전부 저축보다 +1억 3,841만 원`
- `납입원금 대비 184%`

저축 결과와 투자 결과를 독립 요약 카드로 반복하지 않는다. 모바일에서도 두 항목의 의미와 금액이 읽히면 2열을 유지한다.

### 제거 항목

- 반복되는 결과 제목
- 별도 저축·투자 결과 카드
- 월 납입 합계와 세부값의 동시 반복
- 결과 앞의 긴 면책문
- 항상 열린 고급 설정
- 기간 빠른 선택과 기간 `− / +`
- 의미 없는 중첩 카드와 독립 배경
- 화면 본문의 `처음부터 다시`

## 조작

### 기간

- 범위: 0년부터 30년
- slider와 연결된 숫자 입력만 제공한다.
- `0년`은 시점 label에서 `현재`로 표현한다.
- 숫자 입력과 slider는 즉시 동기화한다.
- 기간 빠른 선택과 `− / +` 버튼은 제공하지 않는다.
- 0년 결과에는 시작 원금만 포함하고 월 납입은 아직 반영하지 않는다.
- 0년의 현재 계획과 전부 저축 기준선은 같고 차이는 0원이다.

### 연 기대수익률

기본 조작:

- `5%`
- `9%`
- `13%`
- `직접 입력`

프리셋을 선택하면 숫자 입력을 숨긴다. `직접 입력`을 선택한 경우에만 다음 조작을 표시한다.

- 숫자 직접 입력
- `− / +` 버튼
- 버튼 단위: 0.25%p
- 허용 범위: 0.00%부터 30.00%
- 소수점 둘째 자리까지 허용

변경은 핵심 문장과 그래프에 즉시 반영한다.

### 계산 기준

- 그래프 가까이에 `명목 · 실질` 토글만 항상 표시한다.
- 기준금리와 물가상승률 차이는 접힌 `계산 기준`에 둔다.
- 재투자 가정과 비자문 안내도 같은 영역에 짧게 배치한다.
- 최초 설정에서는 복리, 명목, 기준금리와 물가상승률 용어를 노출하지 않는다.

## 그래프

### 기본 상태

- 현재 계획은 굵은 주곡선과 절제된 면적으로 표시한다.
- 전부 저축은 얇고 대비가 낮은 점선으로 표시한다.
- 색상만으로 선을 구분하지 않는다.
- 전체 폭 그래프를 결과 화면의 중심 시각 요소로 사용한다.
- 축은 `현재`, 주요 연도와 한국식 금액만 표시한다.
- 장식, 긴 설명과 항상 열린 tooltip을 제거한다.

### 탐색 상태

pointer를 움직이면 커서를 따라 세로 기준선과 정보 카드가 이동한다.

정보 카드 위계:

1. 선택 연도
2. 현재 계획 총액
3. 전부 저축 총액
4. 누적 납입원금
5. 현재 계획의 저축 잔액
6. 현재 계획의 투자 잔액

카드는 단순 텍스트 목록이 아니라 현재 계획 총액을 크게 표시하고 나머지 값을 2열로 정렬한다. viewport 끝에 닿으면 기준선 반대편으로 자동 배치한다.

touch에서는 누른 지점에 선택을 고정한다. 다시 누르거나 그래프 밖을 누르면 닫는다. keyboard focus에서는 좌우 방향키로 연도를 이동하며 pointer와 같은 정보를 제공한다.

그래프에는 현재 선택 조건과 최종 결과를 설명하는 텍스트 대체 요약을 제공한다.

## 한국식 금액 표시

금액 formatter는 원 단위 정수 입력을 받아 소수점 없는 한국식 단위 문자열을 반환한다.

### 1억 원 미만

- 백 원 자리에서 반올림한다.
- 천 원까지 표시한다.
- 예: `82,405,500원`은 `8,240만 6천 원`
- 예: `1,234,567원`은 `123만 5천 원`
- 예: `999,500원`은 `100만 원`

### 1억 원 이상

- 천 원 자리에서 반올림한다.
- 만 원까지만 표시한다.
- 예: `482,405,500원`은 `4억 8,241만 원`

### 공통 규칙

- `4.82억 원`, `8240.6만 원` 같은 소수점 표현을 금지한다.
- 조·억·만·천을 정수로 조합한다.
- 값이 0인 중간 단위는 생략한다.
- 그래프 축은 같은 formatter 정책을 사용하되 축 충돌을 피하도록 더 성긴 정수 tick을 선택한다.
- 핵심 문장, 비교값, tooltip과 접근 가능한 텍스트가 같은 반올림 정책을 사용한다.

## Main 자동 동기화

Simulation 진입마다 최신 Main source를 읽는다.

```ts
interface SimulationMainSource {
  monthlySavingsWon: number;
  monthlyInvestmentWon: number;
  mainUpdatedAt: number;
}
```

유효한 완료 draft가 있으면 다음 필드만 최신 Main 값으로 교체한다.

- `source.monthlySavingsWon`
- `source.monthlyInvestmentWon`
- `source.mainUpdatedAt`

다음 Simulation 소유값은 유지한다.

- `initialInvestmentWon`
- `years`
- `expectedAnnualReturnPercent`
- `baseRatePercent`
- `inflationOffsetPercentPoints`
- `amountMode`

Main source 갱신 후 계산은 한 번 수행하고 갱신된 draft를 자동 저장한다. Simulation은 Main repository에 쓰지 않는다.

## 저장 상태

결과 화면의 보조 영역에 시선을 뺏지 않는 상시 indicator를 둔다.

- 저장됨: 작은 중립 또는 긍정 점과 `저장됨`
- 저장 중: 조용한 animation과 `저장 중`
- 실패: 강조 색, 아이콘과 `자동 저장하지 못했어요`

성공 상태는 항상 존재하지만 핵심 문장이나 그래프와 경쟁하지 않는다. 실패해도 현재 입력과 계산 결과를 유지한다. 상태 변화는 `role="status"` 또는 동등한 live region으로 전달한다.

## 오류와 복구

### Main 계획 없음 또는 합계 0원

결과를 만들지 않고 Main 설정 경로를 표시한다.

### Main 읽기 실패

저장된 draft가 유효하면 마지막 결과를 유지하되 `이전 Main 기준`임을 명시한다. 최신 Main 재시도와 Main 이동 행동을 제공한다. 실패한 읽기로 source를 덮어쓰지 않는다.

### Simulation draft 손상

손상 draft를 적용하지 않는다. 최신 Main이 유효하면 최초 2단계 설정으로 복구한다. 기존 v1 storage key와 레거시 데이터는 손상하거나 덮어쓰지 않는다.

### Simulation 저장 실패

계산과 현재 입력은 유지하고 저장 indicator를 오류 상태로 전환한다. Main과 마지막 유효 저장값은 변경하지 않는다.

### 입력 오류

범위 밖 값을 가장 가까운 값으로 조용히 저장하지 않는다. 해당 입력 가까이에 허용 범위와 수정 방법을 표시하고 마지막 유효 계산을 유지한다.

### 계산 오류

결과가 유한하지 않으면 그래프를 렌더링하지 않는다. 문제가 있는 입력과 수정 행동을 결과 가까이에 표시한다.

## 시각 시스템

- Main과 같은 ISF Pearl canvas를 사용한다.
- flat editorial panel과 단색 경계를 사용한다.
- gradient와 과도한 translucent effect를 사용하지 않는다.
- 핵심 문장과 핵심 숫자는 Gowun Batang을 사용한다.
- label, 조작, tooltip과 상태는 Gowun Dodum을 사용한다.
- ISF Sunset은 primary action과 선택에 사용한다.
- ISF Deep Sea는 현재 계획 곡선과 보조 강조에 사용한다.
- 카드 수를 줄이고 관계가 있는 조작, 그래프와 비교값을 하나의 읽기 흐름으로 묶는다.

## 반응형과 접근성

### Desktop

- 전체 폭 대형 그래프를 유지한다.
- 핵심 문장, 조건, 그래프, 비교값과 조작 순서를 바꾸지 않는다.
- pointer tooltip은 cursor를 따라가며 좌우 충돌을 회피한다.

### 768px

- desktop과 같은 정보 순서를 유지한다.
- 여백, tooltip 폭과 조작 간격만 줄인다.
- 그래프를 숨기거나 첫 viewport 밖으로 의도적으로 밀지 않는다.

### 390px

- 핵심 문장과 그래프를 유지한다.
- 조건과 비교값은 의미와 금액이 읽히는 경우 2열을 유지한다.
- 긴 금액은 임의 축약이나 소수점 변환보다 줄바꿈을 우선한다.
- touch tooltip은 viewport 밖으로 넘치지 않는다.

### 공통

- 모든 touch target은 최소 44px이다.
- slider와 숫자 입력은 같은 label 관계와 접근 가능한 이름을 가진다.
- `− / +`는 연 기대수익률과 0.25%p 단위를 accessible name에 포함한다.
- 선택 상태는 색상 외에 `aria-pressed`와 형태로 전달한다.
- graph tooltip 정보는 pointer뿐 아니라 touch와 keyboard로 접근 가능하다.
- `prefers-reduced-motion`에서는 곡선과 저장 indicator animation을 줄이거나 제거한다.
- 가로 overflow가 없어야 한다.

## 컴포넌트 경계

- `SimulationApp`: bootstrap 상태, 최신 Main 동기화와 오류 경로 조정
- `SimulationOnboarding`: 최초 2단계 흐름과 단계 전환
- `StartingPrincipalStep`: 시작 원금 유무와 조건부 금액 입력
- `ScenarioSetupStep`: 기간, 기대수익률과 실시간 preview
- `SimulationHero`: 핵심 문장과 조건 한 줄
- `GrowthChart`: 곡선, 축, pointer, touch와 keyboard 탐색
- `SimulationControls`: 기간과 기대수익률 조작
- `SimulationComparison`: 비교값 두 개
- `CalculationDetails`: 명목·실질, 기준금리, 물가 차이와 가정
- `SaveIndicator`: 저장 상태 표현
- 공통 금액 formatter: 구간별 반올림과 한국식 단위 변환

`SimulationApp`이 각 입력과 SVG 세부 동작을 직접 소유하지 않는다. 계산 domain은 UI 문구나 responsive 상태를 알지 않는다. formatter는 컴포넌트별로 중복 구현하지 않는다.

## 인수 조건

- 제품 지식이 없는 사용자가 질문과 primary action만 따라 최초 설정을 완료할 수 있다.
- 최초 설정은 시작 원금과 기간·기대수익률의 두 단계다.
- 완료 후 재방문은 결과 화면으로 바로 진입한다.
- 결과 화면의 문장형 핵심 정보는 하나다.
- 결과 화면은 조건 한 줄, 전체 폭 그래프와 비교값 두 개를 중복 없이 표시한다.
- 기간은 0~30년 slider와 숫자 입력으로 조정한다.
- 기대수익률은 preset과 조건부 직접 입력으로 조정한다.
- 그래프는 기본 상태가 단순하고 탐색 시 승인된 여섯 정보를 제공한다.
- 금액은 구간별 승인된 한국식 반올림과 단위 규칙을 지키며 소수점을 출력하지 않는다.
- 최신 Main 월 저축·투자는 진입 시 자동 반영되고 Simulation 설정은 유지된다.
- 저장 indicator는 상시 저강도로 존재하며 실패만 강조한다.
- 재설정은 메뉴 안에서 Simulation draft만 초기화한다.
- 390px, 768px와 desktop에서 그래프와 핵심 조작을 사용할 수 있다.
- Simulation은 Main을 변경하지 않는다.
