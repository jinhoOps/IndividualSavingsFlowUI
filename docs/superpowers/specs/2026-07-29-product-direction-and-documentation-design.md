# ISF 제품 방향 및 문서 체계 정리 설계

## 목적

현재 ISF의 제품 기준선과 문서 체계를 실제 개발 상태에 맞춘다.

Main 앱 변경은 완료된 현재 제품으로 취급한다. Simulation, Portfolio와 Account Map은 향후 새로 개발할 앱이며 현재 동명 제품 경로는 준비 화면으로 취급한다. 레거시 코드는 사용자에게 제공하는 병행 제품이 아니라, 아직 옮기지 않은 기능과 데이터 계약을 확인하고 새 구조로 이전하기 위한 임시자산으로 취급한다. 프로젝트 루트에는 현재 개발자가 즉시 읽어야 하는 문서만 남긴다.

## 현재 상태

- Main은 summary-first 화면, Financial Detail Modal 중심 편집, 월간 흐름 시각화와 공통 앱 런처를 제공한다.
- Main 개편 자체는 향후 구현 대상이 아니라 완료된 제품 기준선이다.
- Simulation과 Portfolio의 현재 경로는 최소 journey 연결 상태만 보여주는 준비 화면이다.
- Account Map의 현재 경로는 Main 또는 journey 데이터를 읽지 않는 준비 화면이다.
- 세 앱의 상세 동작과 상태 소유권은 승인된 향후 신규 앱 명세에서 정의한다.
- 일부 레거시 코드와 문서는 기능 마이그레이션 및 호환성 확인을 위해 남아 있다.
- 루트 Markdown은 제품 문서, 에이전트 지침, 과거 요구사항, 메모가 혼재한다.

## 제품 기준선

### Main

Main은 사용자의 월간 가계 흐름을 읽고 수정하는 완성된 시작점이다.

- 기본 화면은 상세 입력보다 현재 상태와 다음 행동을 먼저 보여준다.
- 일반 재무 항목 편집은 Financial Detail Modal에서 완료한다.
- 변경사항은 draft로 유지하고 사용자가 적용해야 저장된다.
- 요약, 계산, Sankey는 동일한 정규화 데이터에 기반한다.
- Account Map은 Main에 내장된 두 번째 편집기가 아니라 별도 목적지다.

향후 기능은 Main을 다시 설계하는 작업이 아니라 이 기준선을 보존하면서 확장한다.

### 현재 준비 목적지와 향후 연결 앱

- 현재 Simulation과 Portfolio 준비 화면은 최소 `JourneySnapshot`만 읽고 상세 편집이나 독립 제품 저장을 소유하지 않는다.
- 현재 Account Map 준비 화면은 Main 또는 journey 데이터를 읽거나 page-owned draft를 저장하지 않는다.
- 향후 Simulation, Portfolio와 Account Map은 승인된 상세 명세에서 자체 가정, 자산 배분, draft와 저장 상태의 소유권을 정의한다.
- 현재와 향후 앱 사이의 데이터 전달은 명시적 CTA, import 또는 connector 계약을 사용하며 Account Map은 Main에 암묵적으로 write-back하지 않는다.

## 레거시 임시자산 정책

### 정의

레거시는 다음 중 하나에 해당하는 코드와 문서다.

- 현재 제품에 아직 이관되지 않은 유효 기능의 원본
- 기존 저장 데이터와 공유 데이터의 호환성을 이해하기 위한 자료
- 새 구현의 동작을 검증하기 위한 비교 기준
- 마이그레이션 완료 여부가 확정되지 않아 일시적으로 보존하는 구현

레거시는 현재 제품 기능, 정상 사용자 경로 또는 신규 구현 패턴으로 취급하지 않는다.

### 허용되는 사용

- 마이그레이션 대상 기능 목록화
- 기존 계산 및 저장 계약 확인
- 새 모듈과 결과 비교
- 구버전 데이터 변환 검증
- 제거 전 회귀 테스트 근거 확보

### 금지되는 사용

- 레거시 UI를 일반 사용자 경로로 다시 노출
- 새 기능을 레거시 모듈 위에 추가
- 현재 제품과 레거시의 양쪽에 동일 기능을 중복 구현
- 레거시 파일이 존재한다는 이유만으로 이를 현재 아키텍처로 문서화
- 마이그레이션 증거 없이 레거시를 즉시 삭제

### 수명주기

각 레거시 기능은 다음 순서를 거친다.

1. 기능과 데이터 책임을 목록화한다.
2. 현재 제품에 필요한 기능인지 판정한다.
3. 필요한 기능은 현재 책임 경계에 맞는 새 모듈로 이관한다.
4. 필요하지 않은 기능은 폐기 결정과 이유를 기록한다.
5. 외부 동작, 저장 데이터, import/export 호환성을 검증한다.
6. 현재 코드의 레거시 참조를 제거한다.
7. 레거시 구현과 관련 문서를 삭제한다.

삭제 완료 조건은 단순한 코드 중복 여부가 아니라 필요한 기능과 데이터 계약의 이관 및 검증 완료다.

## 모듈 경계

### 현재 제품 모듈

- 입력 정규화 및 구버전 호환성
- 월간 snapshot과 장기 projection 계산
- Financial Detail Modal draft 및 검증
- Sankey 데이터 구축과 렌더링
- 앱 런처와 최소 journey snapshot 전달
- 준비 화면의 연결 상태와 복구 행동
- Main 저장 및 compatibility bridge

### 향후 신규 앱 모듈

- Account Map draft 생성, 관계 관리 및 결정적 배치
- Simulation 전략 비교와 자체 가정
- Portfolio 자산 배분과 실행 계획 저장
- 승인된 앱 간 connector와 저장 브리지

### 마이그레이션 경계

- 레거시 기능은 위 현재 제품 모듈 중 책임이 가장 가까운 곳으로 이동한다.
- 책임이 맞는 모듈이 없다면 먼저 독립 인터페이스를 설계한다.
- 단순 파일 복사나 레거시 호출 래핑만으로는 마이그레이션 완료로 보지 않는다.
- 새 모듈은 UI 구현 세부사항보다 외부 동작과 데이터 계약으로 테스트할 수 있어야 한다.

## 문서 체계

### 루트에 유지

#### README.md

역할:

- 현재 제품 소개
- Main, Simulation, Portfolio, Account Map의 관계
- 실행, 빌드, 테스트 진입점
- 현재 지원 범위와 주요 제한
- 상세 문서로 이동하는 링크

README는 과거 단계별 작업 기록이나 임시 아이디어를 보관하지 않는다.

#### DESIGN.md

역할:

- 현재 디자인 원칙
- 색상, 타이포그래피, 간격, 컴포넌트와 반응형 규칙
- 금액 표시와 피드백 등 사용자 경험 계약
- 새 UI가 따라야 할 검증 가능한 기준

DESIGN은 레거시 구현 보존을 제품 디자인 원칙으로 표현하지 않는다.

#### AGENTS.md

역할:

- 작업 역할별 기준 문서 안내
- Main과 레거시 마이그레이션의 최소 저장소 규칙
- CodeGraph 재사용과 단일 초기화 소유권
- 변경 유형별 검증과 충돌·인계 규칙

AGENTS는 PRD, DESIGN, codebase map 또는 계획 문서의 내용을 복제하지 않고 원문으로 연결한다.

### 루트에서 제거

#### CONTEXT.md

현재 제품 용어 중 유효한 내용은 PRD, README, DESIGN 또는 제품 문서로 흡수한다. 레거시 편집기를 사용자 개념으로 남기지 않는다. 흡수 후 루트 파일을 삭제한다.

#### TODO.md

유효한 미래 기능은 PRD의 향후 범위와 현재 Roadmap으로 이동한다. 단편 메모를 루트 백로그로 유지하지 않는다. 이관 후 삭제한다.

#### prd-10.md

백테스트 제거 및 별도 프로젝트 이관 기록은 현재 프로젝트의 제품 PRD에 포함하지 않는다. 역사적 가치가 필요하면 계획 아카이브에 보존하고, 그렇지 않으면 Git 이력을 근거로 삭제한다. 루트 파일은 제거한다.

#### GEMINI.md

현재 사용하지 않는 에이전트별 라우터와 노후 지침은 루트에서 제거한다. 필요한 역사 정보는 Git 이력으로 조회한다.

### 변경된 결정

이 문서의 초기 작성 당시에는 AGENTS를 만들지 않기로 했지만, 다수 에이전트의 역할별 탐색과 CodeGraph 반복 초기화를 막는 저장소 공통 규칙이 필요해졌다. 이 결정은 [Agent Routing Guide Design](2026-07-29-agent-routing-guide-design.md)으로 대체되며 루트에 얇은 `AGENTS.md`를 유지한다.

## PRD 개정 방향

제품 PRD는 다음 상태 구분을 명확히 표시한다.

### 현재 제공

- 완료된 Main 경험
- Simulation과 Portfolio의 journey 준비 화면
- Account Map 준비 화면
- Main 로컬 저장, 공유 인프라와 최소 journey snapshot

### 전환 중

- 레거시 기능 및 데이터 계약의 목록화
- 필요한 기능의 현재 모듈 이전
- 구버전 호환성 검증
- 마이그레이션이 끝난 참조와 구현 제거

### 향후 확장

- 승인된 상세 명세와 마이그레이션 계획에 따른 신규 Simulation
- 승인된 상세 명세와 마이그레이션 계획에 따른 신규 Portfolio
- 승인된 상세 명세와 마이그레이션 계획에 따른 신규 Account Map
- 지출 알림 텍스트 기반 capture
- 가구 데이터 병합
- 과거 지출 비교
- 부동산 구매력 계획
- 앱 간 계획에서 실행으로 이어지는 연결 강화

PRD는 Main 재구축을 미래 요구사항으로 표현하지 않는다. 완료된 Main 동작은 현재 기준선 및 보호해야 할 회귀 계약으로 기록한다.

## 오류 및 예외 처리

- 레거시 기능의 필요 여부가 불명확하면 삭제하지 않고 마이그레이션 목록에서 판정을 대기한다.
- 현재 제품과 레거시 결과가 다르면 사용자에게 관찰되는 동작과 최신 PRD를 기준으로 차이를 조사한다.
- 외부 저장 데이터가 레거시 필드를 포함하면 정규화 또는 compatibility bridge를 거쳐 처리한다.
- 마이그레이션 실패 시 현재 제품 저장 상태를 부분적으로 변경하지 않는다.
- 문서 이동이나 삭제 전에 유효한 정보가 현재 기준 문서에 흡수됐는지 확인한다.

## 테스트 전략

### 현재 제품 회귀

- Main의 summary-first 흐름과 Financial Detail Modal
- draft 적용, 취소, 유효성 검증과 이탈 경고
- 월간 계산, Sankey 및 projection
- Main → Simulation → Portfolio 준비 화면의 최소 snapshot 연결
- 공통 런처의 고정 가용 상태, 현재 위치와 키보드 이동
- 준비 화면의 Main 갱신 시각, 복구 행동과 Account Map 데이터 격리

### 마이그레이션 검증

- 레거시와 현재 모듈의 사용자 관찰 결과 비교
- 레거시 Account Map import·독립 저장, Simulation 가정과 Portfolio 실행 계획의 기능·데이터 계약 목록화
- 구버전 데이터 import와 현재 schema 정규화
- 내보내기 및 공유 데이터 보존
- 마이그레이션 이후 레거시 import, selector, route와 runtime 참조 부재
- 제거 후 전체 타입 검사, 빌드 및 관련 브라우저 회귀

좋은 테스트는 레거시 내부 구현을 고정하지 않는다. 사용자가 보는 결과와 현재 모듈의 공개 데이터 계약을 검증한다.

## 완료 기준

- 제품 PRD가 Main을 완료된 현재 기준선으로 표현한다.
- 레거시가 임시 마이그레이션 자산으로 정의되고 정상 사용자 경로와 분리된다.
- 레거시 제거 조건과 검증 절차가 PRD에 포함된다.
- README, DESIGN과 AGENTS가 각각 제품 진입점, UI 계약, 에이전트 이정표 역할을 수행한다.
- 루트에는 README.md, DESIGN.md와 AGENTS.md만 남는다.
- CONTEXT, TODO, prd-10의 유효 정보가 현재 문서에 흡수된다.
- GEMINI.md가 제거되고 AGENTS.md는 현재 기준 문서를 역할별로 연결한다.
- 문서 링크와 Markdown 형식이 유효하다.
