# 커뮤니티 댓글·이모지 공감

사용자 요청: 2026-09-28. 로그인한 커뮤니티 사용자끼리 공유 비율에 반응하고 댓글로 대화한다. 각 이모지에 인원수를 표시하며 전체 공감 인원은 표시하지 않는다. 동일 사용자의 여러 이모지 반응은 허용하되 같은 이모지는 한 번만 집계한다.

## 화면과 동작

- 카드와 게시물 상세 하단에 이모지 칩과 오른쪽 댓글 아이콘·개수를 표시한다. 카드 전체를 버튼으로 만들거나 댓글 내용을 미리 펼치지 않는다.
- 기존 이모지를 누르면 내 공감을 추가/취소한다. 선택 여부는 색상과 `aria-pressed`, 이모지 설명·인원수로 구분한다. 처리 중 해당 게시물의 중복 제출을 막으며 실패하면 기존 표시를 보존하고 재시도한다.
- 게시물당 동시에 존재하는 이모지 종류는 최대 8개다. 새 종류는 준비된 16개 이모지 중 선택한다. 8종이면 추가 버튼을 숨기며, 기존 칩은 계속 공감할 수 있다. 마지막 공감이 취소되어 0명이면 해당 종류를 제거하고 자리를 다시 연다.
- 모바일에서는 처음 4개만 보여주고 `… +N`으로 나머지를 펼친다. 추가 선택기는 작은 인라인 영역으로 열며 새 모달을 중첩하지 않는다. 조작 영역은 44px 이상, 긴 숫자는 축약 표시와 정확한 접근성 이름을 함께 사용한다. 댓글 버튼은 오른쪽 고정 위치를 유지하고 이모지는 가용 폭에서 줄바꿈한다.
- 댓글 버튼은 공통 ResponsiveDialog의 댓글 화면을 연다. 상세 안에서는 같은 모달의 단계만 바꾸며 뒤로 가기로 비율 상세에 돌아간다. 모바일 88dvh·웹 중앙 모달·기존 Anime.js·drag·초점 복귀 계약을 유지한다.
- 댓글은 최신순 20개씩 이전/다음 페이지로 조회한다. 목록은 본문에서 스크롤하고 입력·등록 버튼은 하단에 유지한다. 빈 목록, 불러오기 실패/재시도, 삭제된 게시물, 작성/삭제 실패를 구분한다.
- 댓글은 텍스트 1~500자(UTF-8 최대 2,000바이트)다. 줄바꿈은 허용하고 HTML/Markdown을 실행하거나 자동 링크로 바꾸지 않는다. 닉네임·작성시각·본문과 본인 댓글 삭제를 제공한다. 답글·댓글 수정·알림·팔로우·공감순 UI는 이번 범위에 추가하지 않는다.
- 실제 미전송 댓글이 있을 때만 닫기/뒤로 가기에 버리기 확인을 둔다. 조회·페이지 이동·저장 완료 후에는 확인하지 않는다. 작성 실패 시 입력을 유지하며 응답 유실 후 재시도는 같은 댓글 ID를 사용한다. 댓글 작성과 이모지 선택은 원본 금융 계획을 변경하지 않는다.

## 저장·보안·예산

- `lounge_reactions`: 게시물·프로필 FK, 이모지 코드. `(post_id, user_id, emoji)` UNIQUE로 중복 카운트 차단. 대상 상태를 명시하는 `set_lounge_reaction` RPC이므로 동일 요청 재시도는 다시 토글하지 않는다.
- `lounge_comments`: 클라이언트 생성 UUID, 게시물·프로필 FK, 검증된 본문, 서버 작성시각. 동일 UUID/계정/본문의 재시도만 기존 결과를 반환한다. 다른 UUID 소유권·내용 위조는 거부한다. 삭제는 본인만 가능하다.
- `lounge_community_activity`: 프로필당 1행의 서버 요청 한도. 댓글은 최소 10초 간격·24시간 구간당 40개, 공감 변경은 1분 구간당 60회. 댓글 삭제로 작성 제한을 되돌릴 수 없다. 무변경·재시도는 한도를 소비하지 않는다.
- 이모지 최대 8종·전역 행 수·요청 한도는 트랜잭션 잠금으로 동시 요청에도 유지한다. 전체 댓글 20,000행·게시물당 500행·전체 공감 100,000행으로 제한한다. 신규 저장은 DB 크기 400MiB 이상에서 거부해 500MB 요금제에 여유를 둔다. 삭제와 기존 무변경 재시도는 허용한다. 행 수 상한은 DB 전체 용량을 보장하지 않으므로 배포 전 현재 크기와 최대 fixture 크기를 기록한다.
- 게시물/계정 삭제 시 댓글·공감 cascade, 활동 메타데이터는 계정 삭제 시 cascade. 영구 브라우저 캐시·이미지·이력 복제를 추가하지 않는다.
- 기존 `lounge_rpc_owner`의 최소 권한·FORCE RLS를 따른다. anon/서비스 키/클라이언트의 직접 테이블 접근을 차단하고 authenticated RPC만 연다. UID·시각·닉네임은 클라이언트에서 받지 않는다. 고정 SQL과 매개변수만 사용하며 빈 search_path와 명시적 schema를 적용한다.
- 댓글 닉네임은 현재 프로필에서 읽어 닉네임 변경이 반영되며 계정 UID/이메일은 응답하지 않는다. 댓글/공감 요약은 별도 배치 RPC로 최대 24개 게시물만 조회한다. 기존 publication 응답·v1~v3 RPC를 바꾸지 않는다.
- 이모지별 인원수와 내 선택 상태를 반환한다. 서버 요약의 전체 공감 인원은 DISTINCT user로 계산하되 화면에는 표시하지 않는다. 이후 정렬에 사용할 수 있는 집계 계약만 마련한다.
- Main·Simulation·Portfolio workspace schema v5/protocol 5, 금액 소유권·백업·기존 Storage 정책은 유지한다.

## 인수 기준

- DB: A/B 교차 공감, 같은 이모지 재시도/경쟁, 여러 이모지와 중복 제거 인원, 8번째/9번째 동시 경쟁, 0명 제거, 금지 코드, 권한·IDOR·텍스트 공격 패턴, 페이지 중복 방지, 댓글 재시도/삭제, 닉네임 반영, 게시물/계정 cascade, 요청/행/용량 상한, 기존 데이터 보존.
- UI: 카드→공감/펼치기/추가/댓글, 댓글 이전·다음·등록·삭제·취소·실패·재시도, 실제 dirty 보호, 늦은 응답/계정 변경, 390/768/1280 overflow·44px·초점·모달 포함·화면 검토.
- 운영: 현재 데이터 digest·용량 확인 → migration → 권한·RPC·기존 digest 확인 → 프런트 배포. 운영 사용자 콘텐츠를 테스트로 생성하지 않는다.
