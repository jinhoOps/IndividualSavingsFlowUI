# Main React 재구성 설계

## 목표

기존 Main의 핵심 기능만 계승해 React, TypeScript, Tailwind CSS 기반으로 새로 구현한다. 기존 DOM 구조, 전역 상태, JavaScript 모듈, CSS 구조를 점진 변환하지 않는다. GitHub Pages 정적 배포와 기존 브라우저 저장 데이터 호환을 유지한다.

첫 릴리스는 공통 React 셸과 Main 완성에 집중한다. Simulation, Portfolio, Account Map은 기존 구현을 유지한다.

## 제품 원칙

- HTML, URL, 폼, 링크 등 웹 표준을 기본 계약으로 삼는다.
- React는 Main의 선언적 UI와 복잡한 화면 상태를 관리한다.
- TypeScript는 도메인, 저장, 계산 경계를 명확히 한다.
- Tailwind CSS는 표현 계층만 담당한다.
- 계산과 검증은 React 밖의 순수 함수로 구현한다.
- 전역 상태, 거대 컴포넌트, 사용 전 추상화를 만들지 않는다.
- 서버 기능 없이 Vite 정적 빌드만 사용한다.
- 사용자 데이터는 로컬에 보관한다.

## 배포와 페이지 구조

Vite 멀티 페이지 구조를 유지한다. React Router 기반 SPA로 합치지 않는다. Main은 기존 실제 HTML 경로에서 독립 React 진입점을 사용한다.

배포 기준 URL:

```text
https://jinhoops.github.io/IndividualSavingsFlowUI/
```

Main 배포 경로:

```text
https://jinhoops.github.io/IndividualSavingsFlowUI/apps/main/
```

경로 규칙:

- 저장소 루트를 무시하는 `"/..."` 절대경로를 사용하지 않는다.
- 앱 간 링크와 공개 파일 경로는 `import.meta.env.BASE_URL`을 기준으로 만든다.
- 번들 에셋은 Vite import를 사용한다.
- 모듈 상대 에셋은 `new URL(path, import.meta.url)`을 사용한다.
- 로컬과 배포 환경에서 같은 경로 생성 함수를 사용한다.
- PWA의 `start_url`, `scope`, `navigateFallback`은 `/IndividualSavingsFlowUI/` 하위 경로를 유지한다.
- 빌드 결과에서 루트 기준 `/assets/...` 경로가 생성되지 않았는지 검사한다.

## 아키텍처

신규 Main 구현은 `src/main` 아래에 둔다.

```text
src/main/
  domain/
  application/
  infrastructure/
  ui/
```

### `domain`

재무 모델, 금액 규칙, 검증, 현금흐름 계산, Sankey 입력 모델을 포함한다. 브라우저 API와 React에 의존하지 않는다.

### `application`

초기 설정, 편집 초안, 적용, 취소, 다시 설정 등 사용자 작업 단위를 조정한다. UI가 저장소 구현을 직접 호출하지 않도록 한다.

### `infrastructure`

LocalStorage, IndexedDB, JSON 백업, 기존 데이터 변환을 구현한다. 도메인 모델과 저장 형식 사이 변환 책임을 가진다.

### `ui`

React 화면, 컴포넌트, Tailwind 스타일, 접근성, 반응형 레이아웃을 구현한다. 계산 규칙을 포함하지 않는다.

핵심 React 경계:

- `MainApp`
- `SetupFlow`
- `SummaryDashboard`
- `FinancialEditor`
- `CashflowSummary`
- `CashflowSankey`
- `ApplyBar`

컴포넌트 이름은 구현 과정에서 책임을 더 잘 드러내는 이름으로 조정할 수 있다. 위 경계의 역할과 데이터 흐름은 유지한다.

## 사용자 흐름

Main 화면과 URL은 하나다. 저장 데이터 상태에 따라 첫 화면이 달라진다.

### 신규 사용자

1. 시작 안내
2. 월 수입 입력
3. 생활비 입력
4. 저축과 투자 입력
5. 계좌와 입금 배분 설정
6. 최종 검토
7. `적용`
8. 요약 화면 진입

단계별 초안을 보존한다. 사용자가 중간에 이탈하면 마지막 완료 단계부터 재개한다.

### 설정 완료 사용자

- 상단에서 이번 달 상태와 저장 상태를 확인한다.
- 수입, 생활비, 저축, 투자 가능액을 핵심 지표로 본다.
- 중앙에서 Sankey 현금흐름을 본다.
- 수입, 생활비, 저축, 투자 요약을 확인한다.
- 각 섹션을 선택해 편집 패널을 연다.

변경은 초안에만 반영한다. `적용`하면 검증, 저장, 재계산을 수행한다. `취소`하면 저장된 원본으로 돌아간다.

### 처음부터 다시 설정

기존 값을 채운 안내 흐름으로 진입한다. 기존 저장 데이터는 즉시 삭제하지 않는다. 마지막 `적용`이 성공할 때 새 데이터로 교체한다. 취소하거나 중간에 이탈하면 기존 적용 데이터는 유지한다.

## 상태와 데이터 흐름

적용 데이터와 편집 초안을 분리한다.

```text
저장 데이터
  -> 기존 데이터 변환
  -> 도메인 모델
  -> 적용 상태
  -> 편집 초안
  -> 검증
  -> 저장
  -> 재계산
  -> 요약과 Sankey 렌더
```

- 적용 상태는 마지막으로 저장에 성공한 데이터다.
- 편집 초안은 적용 전 변경사항이다.
- 계산 결과는 도메인 입력에서 파생하며 별도 원본 상태로 저장하지 않는다.
- 저장 성공 전에는 UI에 적용 완료를 표시하지 않는다.
- 기존 데이터 변환은 원본을 수정하지 않는다.

## 오류 처리

- 기존 데이터 변환 실패 시 원본을 보존한다.
- 변환 실패 시 복구 안내와 원본 JSON 내보내기를 제공한다.
- 초안 검증 실패 시 저장을 막고 해당 입력에 원인을 표시한다.
- 저장 실패 시 초안을 유지하고 재시도를 제공한다.
- Sankey 렌더 실패 시 핵심 수치 요약과 편집 기능은 계속 제공한다.
- 예상하지 못한 화면 오류는 Main 경계에서 복구 화면으로 처리한다.

## 레거시 교체 전략

- 기존 Main JavaScript와 CSS는 기능과 계산 결과를 확인하는 참고 자료로만 사용한다.
- 신규 구현 완료 전 기존 Main 진입점은 유지한다.
- 동일 입력에 대한 핵심 계산 결과를 기존 구현과 비교한다.
- 신규 사용자와 기존 사용자 흐름 검증 후 Main 진입점을 새 구현으로 교체한다.
- 교체 후 Main에서만 쓰는 레거시 파일을 제거한다.
- 공유 파일은 Simulation, Portfolio, Account Map 사용 여부를 확인한 뒤 제거한다.
- 첫 릴리스에서 다른 앱 내부 코드를 전환하지 않는다.
