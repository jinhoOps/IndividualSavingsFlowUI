# Portfolio 결과·샘플 탐색 재설계

상태: 2026-09-16 사용자 구현·푸시 승인. 후속 지시로 별도 수정 버튼을 배분 행 진입으로 변경하고 바깥 클릭·변경 폐기 확인을 포함했다.

## 목표와 근거

결과의 편집 진입점을 배분 목록에 연결하고, 금액 표시를 일관되게 만들며, 샘플 탐색·조정·초안 반영을 웹과 모바일에서 끝까지 수행할 수 있게 한다.

2026-09-16 Orca 내장 브라우저에서 현재 로컬 코드와 합성 fixture(월 투자금 800,000원, VOO 70%, 금 30%)로 확인했다. 운영 계정 데이터는 사용하지 않았다.

1. 결과: 제목 옆 독립 연필 버튼을 확인했다. 금액 보기 ON에서는 총액과 VOO 560,000원, 금 240,000원, 현금 0원이 표시됐다. 사용자 제보의 금액 미표시는 이 조건에서 재현되지 않았다.
2. 결과 → 편집 → 샘플: 제목과 돌아가기 버튼이 두 번 나온다. 1280×720에서 샘플 본문 높이는 1,183px이고 부모 패널은 720px다. 부모 overflow는 hidden, 샘플 본문은 스크롤 영역 밖에 있다.
3. 샘플 선택 후: 390×844, 768×1024, 1280×600에서 목록 아래에 붙는 조정·미리보기·반영 행동이 화면 아래로 잘린다. 390px에서는 내부 돌아가기 텍스트도 줄바꿈된다.

캡처는 `/tmp/isf-portfolio-audit/`에 저장하고 직접 열어 확인했다. 가상 키보드, 실제 모바일 기기, 스크린리더 및 운영 배포에서의 금액 증상은 아직 검증하지 않았다.

관련 계약: [PRD](../../ways-of-work/plan/isf-rebuild/connected-financial-planning-workspace/prd.md), [DESIGN](../../../DESIGN.md), [편집 위계 설계](2026-09-16-portfolio-editor-hierarchy-design.md).

## 방향 선택

- 현재 긴 샘플 화면에 스크롤만 추가: 잘림은 해결하지만 선택한 구성의 조정 영역까지 긴 이동이 남는다.
- **목록과 선택한 구성의 상세를 분리: 추천.** 넓은 화면은 나란히, 좁은 화면은 목록 → 상세로 이동한다. 선택 결과와 다음 행동을 가까이 둔다.
- 모든 배분 편집을 다단계 설정으로 변경: 기존 항목 하나를 수정하는 일까지 길어져 채택하지 않는다.

## 1. 결과 화면

- 제목 옆 독립 연필 버튼을 제거한다.
- `.portfolio-allocation-row__select`가 이름·비율·금액을 포함한 행 전체를 차지하며, 누르면 배분 편집기로 진입한다. 별도 수정 버튼은 두지 않고 최소 44px 터치 영역을 유지한다.
- 웹·모바일 모두 같은 행 진입 방식을 사용한다.
- 읽는 순서는 핵심 요약 → 선택적 월 투자금 → 최대 비중 설명 → 100% 막대 → 항목 목록이다.
- 목록 행은 왼쪽 색상·이름, 오른쪽 비율을 주 정보로 둔다. 금액 ON이면 비율 바로 아래에 금액을 보조 정보로 표시한다.
- 모바일에서도 비율과 금액은 하나의 오른쪽 묶음이다. 긴 이름은 왼쪽에서 줄바꿈하며 금액과 겹치지 않는다. 행 높이는 내용에 따라 늘어난다.
- 행 hover·focus는 대응하는 막대를 강조하고, 클릭·Enter·Space는 편집을 연다. 닫으면 진입 행으로 돌아가며 해당 행이 교체되었으면 첫 결과 행으로 초점을 복원한다.

## 2. 금액 보기 계약 및 미해결 증상

- 관리 메뉴의 기존 금액 보기 설정 하나로 총액과 모든 항목·현금 금액을 동시에 전환한다.
- OFF에서는 원화 금액을 결과 DOM과 접근성 설명에 넣지 않는다. ON에서는 재진입·새로고침 없이 즉시 나타난다.
- 결과 금액은 적용 배분과 최신 Main 투자금을 기준으로 한다. 편집 중인 초안의 금액이 결과에 섞이지 않는다.
- 금액 전환은 배분, 선택 항목, 정렬, 저장 dirty 상태를 바꾸지 않는다. 보기 설정은 기존 별도 저장 계약을 유지한다.
- 편집 화면의 금액 입력은 결과의 숨김 설정과 독립적이다.
- 구현 첫 단계에서 사용자 증상을 배포 화면에서도 재현한다. 배포 번들과 현재 코드의 일치 여부, 설정 전달, 실제 DOM, CSS 가림을 순서대로 확인한다. 현 단계에서는 특정 원인이나 수정 완료를 주장하지 않는다.

## 3. 샘플 화면의 정보 구조

- 편집기 본문에 보조 진입점 `샘플로 구성하기`를 둔다. 헤더는 제목과 닫기 역할만 맡는다.
- 샘플은 같은 편집 흐름 안의 하위 화면이다. 별도 중첩 dialog를 추가하지 않는다.
- 제목은 `샘플로 구성하기` 하나만 표시한다. 긴 환영 제목과 내부 돌아가기 버튼은 제거한다.
- 상단 모드는 `샘플 선택 / 직접 조합`으로 표시한다. 색이 강한 실행 버튼 두 개 대신 기존 공통 선택 컴포넌트의 낮은 강조를 사용한다.
- 전체 7개는 기존 방어·성장·공격 지향 구간과 속성을 유지한다. 상대적 탐색 구간이며 확정적인 안전 순위로 표현하지 않는다.
- 목록 항목은 구성 이름, 비율, 배당·인컴/인덱스/레버리지 등의 속성을 보여준다. 위험 구간마다 큰 테두리 카드를 중첩하지 않고 소제목과 행 구분으로 묶는다.
- 필터는 `전체 / 방어 / 성장 / 공격`의 짧은 표시를 사용하고 좁은 폭에서는 2×2로 배치한다. 잘린 가로 스크롤을 필수 조작으로 만들지 않는다.
- 선택한 구성 상세는 구성명 → 비율 막대 → 대상별 비율·금액 → 주력 비율 조절 → 구성 설명 순서다.
- 주력은 50~90%, 5% 단위 조작을 유지한다. 보조 비율 재분배 규칙은 기존 도메인 계약을 유지하고 결과를 즉시 보여준다. 직접 조합은 중복 대상과 합계 오류를 해당 입력 옆에서 알린다.
- 비율 변경 후에는 `샘플에서 조정한 구성 · 위험 구간 미평가`를 표시한다.
- 선택 전에는 임의로 첫 샘플을 적용 후보로 확정하지 않는다. 상세 공간에는 선택 안내를 표시한다.
- GOLD는 금 자산 전체라는 기존 설명을 유지한다. 투자 성향 검사는 후속 선택 기능이며 이 흐름의 필수 단계로 추가하지 않는다.

## 4. 웹·모바일 배치

| 화면 | 샘플 탐색 배치 | 이동·스크롤 |
| --- | --- | --- |
| 1100px 이상 | 최대 960px 너비의 넓은 패널 안에 목록 약 320px + 선택 상세 가변 너비 | 헤더 고정, 두 영역은 각각 필요한 만큼 세로 스크롤. 상세 아래 초안 반영 행동 고정. 선택 시 상세만 갱신 |
| 769~1099px | 최대 640px, 화면 좌우 여백을 확보한 단일 열 패널 | 목록 → 상세 전환. 화면당 본문 스크롤 하나 |
| 768px 이하 | 샘플 탐색 중에는 전체 높이 화면으로 확장 | 목록 → 상세 전환. 상단 헤더와 상세의 하단 행동 사이 본문만 스크롤 |

- 일반 배분 편집기의 기존 모바일 sheet/웹 panel 계약은 유지하고, 내용이 많은 샘플 탐색에서만 위 배치를 적용한다.
- 높이는 고정 픽셀 대신 사용 가능한 viewport를 기준으로 한다. 헤더·본문·footer를 명시적으로 나누고 본문이 남은 높이 안에서 줄어들고 스크롤되게 한다.
- 선택 전에는 비어 있는 적용 footer 공간을 예약하지 않는다. 상세 화면에서만 한 개의 주 행동을 제공한다.
- 모바일 하단 safe area를 확보한다. 키보드가 열리면 입력과 오류에 접근할 수 있고 footer가 마지막 내용을 덮지 않아야 한다.
- 폭이 바뀌어도 선택·비율 조정·필터 상태를 유지한다. 2열에서 단일 열로 바뀔 때 선택이 있으면 상세, 없으면 목록을 표시한다.

## 5. 돌아가기·초안 반영

- 뒤로가기는 헤더 왼쪽 한 곳만 사용한다. 단일 열 상세에서는 `샘플 목록`, 목록과 넓은 화면에서는 `배분 편집`으로 목적지를 명시한다.
- 단일 열 상세 → 목록은 선택과 조정값을 보존하고 선택했던 행 및 스크롤 위치로 돌아간다.
- 샘플 탐색 → 편집은 반영 전 기존 초안을 그대로 유지한다. 탐색 중 후보는 같은 편집 세션 안에서 보존하고 편집 종료 시 정리한다.
- Escape는 현재 화면의 뒤로가기와 같은 한 단계만 수행한다. 키보드 초점은 새 화면 제목 또는 복귀한 진입점으로 연결한다.
- 일반 편집의 닫기·취소·Escape 및 편집 화면 바깥 클릭은 같은 종료 경로를 사용한다. 변경이 없으면 즉시 닫으며, 변경된 초안·미완료 현금 입력·선택한 샘플이 있으면 `계속 수정 / 변경 버리기` 확인을 제공한다. 확인 취소 시 입력을 유지한다. 패널 내부 여백 클릭은 닫기로 처리하지 않는다. 중첩 대상 편집은 기존 최상위 dialog만 닫는 계약을 따른다.
- 상세 footer의 주 행동은 `이 구성으로 초안 채우기`다. 안내는 `아직 적용된 배분은 바뀌지 않아요`로 통일한다.
- 기존 대상 또는 수동 현금 배분을 교체해야 하면 같은 화면 안에서 확인 상태를 표시한다. 기존 대상 수와 새 대상 수, 현금 변경을 요약하고 `계속 살펴보기 / 초안 바꾸기`를 제공한다. 확인 화면 아래로 다시 스크롤하게 하지 않는다.
- 초안 반영 후 배분 편집기로 돌아온다. 실제 적용은 기존 전체 배분 적용과 저장 성공 절차를 따른다.

## 6. 구현 범위와 완료 기준

주요 범위는 `PortfolioSummary`, `PortfolioEditSurface`, `PortfolioExamplePicker`, 최초 설정의 샘플 진입, 관련 CSS·단위·브라우저 테스트다. 화면 제목·뒤로가기·본문·footer는 화면을 소유한 상위 컴포넌트가 관리하고, 샘플 콘텐츠가 중복으로 만들지 않는다.

DESIGN과 PRD의 편집 진입점·샘플 화면·바깥 클릭 계약을 갱신한다. Main read-only, 최대 10개 대상, draft/applied, workspace schema v5·protocol 5 및 보존 데이터 계약은 유지한다.

검증 항목:

- 390×844, 390×600, 768×1024, 1024×600, 1280×720, 1440×900에서 전체 흐름을 수행한다.
- 7개 샘플 모두 접근 가능하고 마지막 샘플의 조정·초안 반영까지 pointer·touch·keyboard로 완료한다.
- 첫 설정과 재편집 양쪽에서 제목·뒤로가기·주 행동이 중복되지 않는다.
- 금액 ON/OFF와 새로고침 후 모든 대상·현금·총액을 각각 검증한다. 총액 하나만 확인하는 테스트로 대체하지 않는다.
- 긴 이름, 10개 대상, 큰 금액, 0원 현금, 200% 확대에서 가로 넘침과 내용 가림이 없다.
- 목록 복귀, 닫기, Escape, 화면 폭 전환에서 초점·선택·초안 보존을 확인한다.
- 샘플 선택/조정/돌아가기는 적용 계획을 변경하지 않으며 최종 적용 전후 저장 경계를 검증한다.
- TypeScript 검사와 관련 단위·Portfolio 브라우저 테스트를 실행한다. 실기기 키보드 검증을 하지 못했다면 별도 한계로 기록한다.
