# Main 빠른 설정 UX 재설계

## 목표

Main의 첫 경험을 가계부 작성이 아닌 월 현금흐름 파악에 맞춘다.
사용자는 2~3분 안에 총수입 100% 중 소비, 저축, 투자, 남는 돈의 비율을 확인한다.

핵심 원칙:

- 한 번에 하나의 판단만 요구한다.
- 이전 입력이 이후 단계에서도 계속 보인다.
- 정확한 분류보다 빠른 규모 파악을 우선한다.
- Main은 다른 앱의 상세 모델을 포함하지 않는 작은 중심 데이터만 소유한다.
- 다른 앱 호환은 후속 설계에서 adapter 경계로 다룬다.

## 범위

포함:

- 신규 사용자 빠른 설정 흐름
- 금액 입력과 빠른 조정
- 단계별 실시간 현금흐름 요약과 게이지
- 최종 배분 확인
- Main schema v2
- 중간 이탈 복구와 저장 오류 처리

제외:

- 계좌, 입금 배분, 자동이체, 계좌 관계
- Account Map을 포함한 다른 앱 연결과 호환 구현
- 기존 Main v1 데이터 migration
- 상세 지출 항목과 가계부 기능

## 사용자 흐름과 문구

화면은 시작, 네 입력 단계, 최종 확인으로 구성한다.

### 시작

- 제목: `한 달 돈의 흐름, 2분이면 확인할 수 있어요.`
- 설명은 수입과 지출 규모를 간단히 입력하면 남는 돈을 확인할 수 있다는 내용으로 제한한다.

### 1단계: 실수령액

- 제목: `한 달에 실제로 들어오는 돈은 얼마인가요?`
- 필드: `월 실수령액`
- 수입 이름이나 수입별 상세 내역은 받지 않는다.

### 2단계: 주거비

- 제목: `주거비로 매달 얼마가 나가나요?`
- 필드: `월 주거 고정비`
- 도움말: `월세 또는 전세대출 이자, 관리비, 공과금을 합친 금액`
- 상세 항목을 나누지 않고 합계 한 개만 받는다.

### 3단계: 생활비

- 제목: `그 밖의 생활비는 보통 얼마인가요?`
- 필드: `월평균 생활비`
- 도움말: `식비, 교통비, 경조사비 등 최근 몇 달의 평균`

### 4단계: 저축과 투자

- 제목: `매달 저축과 투자는 얼마나 하나요?`
- 도움말: `정해둔 금액이 없다면 건너뛰어도 돼요.`
- 필드: `월 저축액`, `월 투자액`
- 두 값 모두 선택 입력이며 0원으로 진행할 수 있다.

### 최종 확인

총수입 100%를 다음 구간으로 나누어 보여준다.

- 소비
- 저축
- 투자
- 남는 돈

소비는 주거 고정비와 평균 생활비의 합이다. 최종 적용 후 Main 대시보드로 진입한다.
계좌 관련 CTA나 기능은 이번 범위에 포함하지 않는다.

## 금액 입력

금액 필드는 입력 중에도 천 단위 쉼표를 표시한다.

- 예: `3,000,000`
- 입력 오른쪽에 `원`을 별도 표시한다.
- 중간 삽입, 삭제, 선택 영역 교체, 붙여넣기 후에도 사용자가 의도한 숫자 위치에 caret을 유지한다.
- 숫자가 아닌 문자는 금액에서 제외한다.
- 빈 값은 초안에서 0원으로 처리한다.
- 음수는 허용하지 않는다.

각 금액 필드에 다음 빠른 조정 버튼을 제공한다.

- `−10만`
- `+10만`
- `+50만`
- `초기화`

감소 결과는 0원 미만이 되지 않는다.

## 단계별 현금흐름 맥락

실수령액 입력 후 모든 입력 단계 상단에 현재 상태를 유지한다.

- `월 수입 320만 원`
- `현재 계획 180만 원`
- `남는 돈 140만 원`

현재 계획은 소비, 저축, 투자의 합이다. 값은 입력 즉시 갱신한다.

입력 단계에서는 총수입 대비 현재 계획 비율을 단일 가로 게이지로 표시한다.
게이지 hover, 키보드 focus, 모바일 tap 시 tooltip에는 `56.3%`처럼 비율만 표시한다.
같은 정보는 pointer 없이도 접근할 수 있어야 한다.

최종 확인에서만 소비, 저축, 투자, 남는 돈을 색 구간으로 나눈 누적 바를 표시한다.
각 구간은 금액과 비율을 확인할 수 있어야 하며 색만으로 의미를 구분하지 않는다.

## 초과와 경계 상태

- 실수령액이 0원이면 다음 단계 진행을 막고 수입 입력을 안내한다.
- 주거비, 생활비, 저축, 투자는 각각 0원을 허용한다.
- 현재 계획이 수입을 넘어도 입력을 제한하거나 자동 보정하지 않는다.
- 100% 초과 시 게이지를 경고 상태로 바꾸고 `월 수입보다 20만 원 많아요`처럼 초과액을 표시한다.
- 수입이 0원일 때 비율을 계산하지 않고 `수입을 먼저 입력해주세요.`를 표시한다.
- 정확히 100%이면 남는 돈을 0원으로 표시한다.

## 데이터 모델

Main은 상세 항목 배열이나 계좌 참조 없이 다음 schema만 소유한다.

```ts
interface MainData {
  schemaVersion: 2;
  updatedAt: number;
  monthlyNetIncomeWon: number;
  monthlyHousingWon: number;
  monthlyLivingWon: number;
  monthlySavingWon: number;
  monthlyInvestmentWon: number;
}
```

계산값은 저장하지 않고 순수 함수로 구한다.

```text
소비 = 주거 고정비 + 평균 생활비
현재 계획 = 소비 + 저축 + 투자
남는 돈 = 실수령액 - 현재 계획
항목 비율 = 항목 / 실수령액
```

기존 Main v1 데이터는 변환하지 않는다. v1만 발견되면 신규 설정으로 시작한다.
다른 앱이 미래에 Main 데이터를 소비할 때는 schema v2 core를 직접 확장하지 않고 별도 adapter를 사용한다.
adapter의 구체적인 계약, 버전 정책, 앱 간 동기화는 후속 설계로 남긴다.

schema v2는 기존 key와 섞지 않는다.

- 적용 데이터: `isf-main-v2`
- 설정 진행 상태: `isf-main-v2-setup-progress`

v2가 있으면 v2만 로드한다. v2가 없고 v1만 있으면 v1을 읽거나 지우지 않고 신규 설정을 시작한다.

## 컴포넌트와 데이터 흐름

- `SetupFlow`: 시작, 입력 단계, 최종 확인 이동
- `MoneyField`: 표시 문자열, caret, 정규화, 빠른 조정
- `FlowContextSummary`: 수입, 현재 계획, 남는 돈
- `UsageGauge`: 입력 단계의 단일 계획 비율
- `AllocationBar`: 최종 확인의 누적 배분
- cashflow 계산 모듈: 합계, 남는 돈, 비율, 초과액
- repository: schema v2 저장, 로드, 설정 진행 상태 보존

적용 데이터와 설정 초안은 분리한다.
입력할 때는 초안만 바꾸고 마지막 적용 성공 후 저장 데이터로 교체한다.
중간 이탈 시 현재 단계와 초안을 보존한다.

## 오류 처리

- 저장 실패 시 초안을 유지하고 재시도 가능한 오류를 표시한다.
- 손상되거나 유효하지 않은 schema v2 저장값은 사용하지 않고 신규 설정으로 진입한다.
- 계산 함수는 `NaN`, 무한대, 음수를 유효한 저장값으로 받지 않는다.
- tooltip이 열리지 않아도 요약 금액과 게이지 자체로 핵심 상태를 이해할 수 있어야 한다.

## 기술 스택과 배포 제약

현재 lockfile에서 확인한 설치 버전을 유지한다.

- React 19.2.5
- TypeScript strict mode
- TypeScript 5.9.3
- Vite 5.4.21 MPA build
- Tailwind CSS 4.2.4 Vite plugin
- Vitest 4.1.5 + jsdom 26.1.0
- Testing Library
- Playwright 1.60
- vite-plugin-pwa 0.21.1
- GitHub Actions Node 22

GitHub Pages는 저장소 하위 경로에서 서비스된다.

- Vite base: `/IndividualSavingsFlowUI/`
- Main URL: `/IndividualSavingsFlowUI/apps/main/`
- 내부 이동과 asset은 루트 `/`를 가정하지 않는다.
- PWA `start_url`, scope, navigation fallback도 하위 경로를 유지한다.
- 정적 배포이므로 서버 API나 server-side session에 의존하지 않는다.

`package.json`의 Tailwind 최소 버전 표기는 alpha지만 lockfile에는 stable 4.2.4가 설치되어 있다.
이번 UX 변경에서 dependency 범위 정리, 버전 업그레이드, 교체는 하지 않는다.
기술 스택 변경은 별도 작업으로 분리한다.

## 검증

단위 테스트:

- 금액 문자열 정규화
- 쉼표 재포맷 후 caret 보존
- 중간 삽입, 삭제, 선택 교체, 붙여넣기
- 네 빠른 조정 버튼과 0원 하한
- 소비, 현재 계획, 남는 돈, 비율 계산
- 수입 0원, 정확히 100%, 100% 초과
- schema v2 저장과 로드
- v1 무시와 손상된 v2 복구
- 빈 배열이나 객체를 반환하는 함수가 있다면 호출 간 참조 독립성

컴포넌트 테스트:

- 단계 이동과 이전 값 유지
- 모든 후속 단계에서 실시간 요약 갱신
- 단일 게이지와 최종 누적 바
- 오류 및 초과 상태 문구
- tooltip의 hover, focus, tap 접근
- 중간 이탈 후 같은 단계와 초안 재개

E2E:

- 신규 사용자가 네 입력 단계를 거쳐 적용
- 모바일 viewport 금액 입력과 게이지 조작
- 키보드만으로 전체 흐름 완료
- GitHub Pages 하위 경로 직접 진입과 새로고침
- 적용 후 대시보드 수치 일치

## 성공 기준

- 대표 신규 사용자가 2~3분 안에 설정을 완료한다.
- 300만 원을 320만 원으로 중간 수정할 때 caret이 예상 위치를 벗어나지 않는다.
- 지출, 저축, 투자 입력 중 수입과 남는 돈을 화면 이동 없이 확인한다.
- 최종 화면에서 총수입 100%의 배분을 한눈에 이해한다.
- Main 저장 데이터에 계좌나 다른 앱 전용 필드가 없다.
- GitHub Pages 배포 경로에서 새 설정, 재개, 적용이 동작한다.
