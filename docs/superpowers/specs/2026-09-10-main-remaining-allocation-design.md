# Main 남는 돈 분배 도우미

작성일: 2026-09-10. 사용자 요청: 남는 돈 금액에서 저축·투자에 더 넣을지 묻고 분배를 돕는다. 기존 UX와 Main 소유권 안에서 구현한다.

기준: [Product PRD](../../ways-of-work/plan/isf-rebuild/connected-financial-planning-workspace/prd.md), [DESIGN](../../../DESIGN.md), [지출 도우미](2026-09-10-main-expense-assistant-design.md).

## 동작

- 남는 돈의 금액·지팡이·`저축·투자에 나누기`에서 진입한다. 명칭·비율은 도넛 탐색을 유지한다. 다른 Main 편집기와 중첩하지 않는다.
- “남는 돈을 더 모아볼까요?”와 함께 현재 남는 돈을 표시한다. 추가 금액은 0원에서 시작하며 열기만으로 저장하거나 draft를 만들지 않는다.
- `저축에 전부`, `투자에 전부`, `반씩 나누기` 또는 두 원 단위 입력으로 추가분을 정한다. 선택 변경은 추가 예정분을 교체한다. 반씩의 홀수 1원은 저축에 둔다.
- 저축·투자의 현재 금액과 반영 후 금액, 나눈 뒤 남는 돈을 함께 표시한다. 일부만 배분할 수 있다. 음수·소수·안전 정수 범위 밖·남는 돈 초과 입력은 적용하지 않는다.
- `이렇게 나누기`에서 기존 월 저축·투자에 각각 한 번 더한다. 수입·주거·생활비, 지출 답변과 다른 앱 slice를 보존한다. 저장 완료 전에는 요약을 바꾸지 않는다.
- 남는 돈이 0원 또는 음수라면 `배분 상태 확인` 진입점으로 상태와 월 금액 편집 안내만 제공한다. 입력이나 저장은 제공하지 않는다.
- `나중에`·닫기·Escape·backdrop은 변경 시 폐기를 확인한다. 거절하면 입력을 유지한다. 성공/취소 후 진입점으로 focus를 복원하며, 복구 때문에 진입점이 사라진 경우 요약 제목으로 돌린다.

## 저장과 복구

- 기존 Main draft/controller/repository와 `save_main` protocol 5를 사용한다. 별도 질문 이력, workspace 필드, localStorage 키, backup 형식 또는 SQL migration을 추가하지 않는다.
- 유효한 작성 중 금액은 기존 `main` 계정 복구 초안으로 보관된다. 세션 만료·재방문 복구는 기존 월 금액 편집에서 검토하며 자동 적용하지 않는다. 초과 금액은 현재 dialog에서 수정하고 잘못된 원 단위 입력은 오류로 알린다. 복구 기록은 마지막 유효한 Main 초안을 보존하며, 첫 입력부터 잘못된 경우에도 취소 시 계정의 미저장 표시를 정리한다.
- 중복 제출은 UI/controller gate로 차단한다. 저장 결과 불명은 패널 안에서 같은 mutation의 결과를 다시 확인하므로 두 번 더하지 않는다.
- 다른 기기의 변경과 충돌하면 추가분을 자동 재적용하지 않는다. 입력을 유지하고 도우미를 닫아 기존 계정의 `최신 저장 계획 보기`로 이동하도록 안내한다. 최신 계획을 채택한 후 새 남는 돈을 기준으로 다시 나눈다.
- 오프라인에서는 기존 계정 정책대로 금융 변경 진입점과 입력을 잠근다.

## 화면과 검증

767px 이하 bottom sheet, 768px 이상 우측 modal panel. 배경 dashboard 비활성화, focus trap, Escape, 44px 조작 영역과 reduced motion을 제공한다. footer는 유지하며 작은 높이에서는 내용만 스크롤한다. 원 단위 반영 전후는 반올림 없이 표시한다.

필수 검증은 계산 경계 unit, 기존 Main unit, 타입 검사, 계정 HTTP 경계 Playwright의 390/768/1280px·부분 배분·선택 교체·취소·재방문·0원/적자·응답 유실·revision 충돌과 Main/공유 소비자 회귀다. 계정 모의 HTTP 검증은 실제 운영 계정 write 검증과 구분해 기록한다.
