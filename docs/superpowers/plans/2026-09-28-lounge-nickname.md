# 라운지 최초 닉네임 설정

사용자 승인: 라운지 랜딩에서 기능 안내·최초 닉네임 설정, 변경 기능 없음 안내, 특수문자 `- . @`만 허용. 중복 불가·영문 대소문자 구분 없음 확인.

## 설계

- 로그인 후 등록된 라운지 프로필이 없으면 소개·닉네임 설정 랜딩을 연다. 프로필 조회 실패는 재시도로 처리하며 미등록으로 간주하지 않는다. 등록 이후에는 목록으로 바로 진입한다. 기존 게시물 링크도 설정 후 이어서 연다.
- 소개는 비율 둘러보기·내 투자금으로 적용·내 구성 공유 세 항목이며, 정확한 금액 제외·자산 규모 선택 공유를 안내한다.
- 2~20자, 한글 완성형/호환 자모·ASCII 영문/숫자·`- . @`만 허용한다. 공백·이모지·기타 특수문자와 기호만 있는 이름은 거부한다. NFC로 통일하고 영문 대소문자를 구분하지 않는 UNIQUE 이름으로 저장한다. IME 조합 중 입력을 강제로 변경하지 않는다.
- `닉네임 확인` → 공통 바텀시트/모달에서 이름을 다시 보여주며 `최초 설정 후 변경할 수 없어요` → `이 닉네임으로 시작`으로 한 번 등록한다. 현재 변경 기능은 제공하지 않는다.
- `lounge_profiles`: 계정당 1행, 닉네임 UNIQUE, 수정 API 없음. 직접 접근 차단·FORCE RLS·전용 역할·등록의 동시 요청/응답 유실 재시도·5,000행 상한을 검증한다. 계정 삭제 시 cascade.
- 기존 자유 입력 별명은 migration에서 자동 고정하지 않는다. 사용자가 닉네임을 확정할 때 자신의 기존 게시물 별명만 함께 갱신하고 version을 올린다. 기존 공유에도 적용된다는 안내를 확인 단계에 둔다.
- 새 게시 RPC는 별명 인자를 받지 않고 계정의 고정 닉네임을 사용한다. 구버전 게시 경로도 DB trigger로 미등록 쓰기를 차단하고 등록된 닉네임을 강제해 다른 이름으로 게시하지 못하게 한다. 기존 게시물 읽기·삭제는 유지한다.
- 정확한 금액·자산 구간 선택, Main·Simulation·workspace schema v5/protocol 5·보존 데이터는 유지한다. 프로필/게시물은 workspace 백업에 넣지 않는다.
