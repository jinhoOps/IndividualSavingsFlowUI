# Portfolio 비율 편집·최종 적용 핫픽스

## 문제와 확인 근거

- 대상 편집 UI는 금액만 받아 비율 기준 편집 경로가 없었다. 기존 draft의 `inputMode`와 share 단위를 활용한다.
- 사용자가 샘플 주력 비율 조정 → `초안 바꾸기` 뒤 저장 버튼 소실을 신고했다. 기존 코드에서 footer는 dirty일 때만 나타났다. 동일 구성/변경 없음에서도 최종 행동 위치를 유지하도록 바꾼다.
- 수정 전 로그인 테스트의 390·768·1280px 샘플 변경과 최종 저장은 통과했고, opacity 및 화면 캡처에서도 적용 버튼이 보였다. 따라서 신고된 유효 변경의 버튼 소실 원인을 특정했다고 주장하지 않는다. 짧은 모바일·저장 지연·직접 조합까지 회귀 범위를 넓히고 적용 경로를 명시적으로 유지한다.

## 구현

1. 대상 추가·수정에 공통 `금액 / 비율` 선택을 둔다. 샘플 초안은 기존 percentage 모드를 따르고 같은 초안 내 선택을 유지한다.
2. 비율 입력은 소수점 넷째 자리, 0~100 범위와 ±1·5%p 조정을 제공한다. 환산 금액은 정확한 원 단위로 표시한다. 기존 대상 최소 1,000원·전체 투자금 초과·중복 이름 검증을 유지하며 다른 자산 비율을 임의로 줄이지 않는다.
3. 금액은 기존 amount commit 경로로 전달한다. 입력 방식 전환은 금액을 재계산하지 않는다. 비율을 실제 수정할 때만 월 투자금 × 비율을 원 단위로 반올림한다.
4. 미완료 복구에 선택 방식·raw 비율을 선택 필드로 보존한다. 기존 금액 복구 payload는 그대로 읽고 쓴다. 잘못된 비율도 복구하고 완료는 막는다.
5. 전체 편집 footer는 항상 표시하며, 변경이 없으면 상태를 알리고 적용만 비활성화한다. 대상/샘플 하위 단계에는 상위 적용 버튼을 노출하지 않는다. 고정 footer가 차지하는 공간만큼 목록·추가 버튼은 본문에서 스크롤해 접근한다. 기존 clean 화면의 모든 행 첫 화면 노출 조건은 이 규칙으로 대체한다.
6. 샘플 반영은 항목 편집 상태와 오류를 초기화하고, 목록 복귀 뒤 적용 버튼으로 focus를 옮긴다. 단순 샘플 취소는 샘플 진입 버튼으로 돌아온다.

## 데이터 경계

- Main 금액은 읽기 전용이다. Portfolio plan/draft의 저장 형식, schema v5·protocol 5와 `locations`/`accountMap`을 보존한다.
- 새 Supabase 테이블·migration·운영 설정은 필요 없다. 복구 payload의 선택 필드만 늘어난다.
- 초안 서버 저장과 계획 최종 적용은 별개이며 적용 확인·실패/충돌 처리는 유지한다.

## 검증

- 구현 전: 비율 입력 테스트는 비율 버튼 부재로 실패, clean footer 테스트는 적용 버튼 부재로 실패했다.
- `npm run check:ci`: 타입·harness 및 전체 단위 1,327개 통과.
- 최초 집중 Playwright: 8개 통과. 최초 설정/재편집 직접 조합, 390·768·1280px 샘플 교체와 저장 지연 중 적용 표시, 비율 수정·초과 거절·최종 적용·서버 재조회·다른 slice 보존.
- 첫 회귀는 61개 통과·4개 실패했다. 3개는 footer 상시 표시로 바뀐 clean 화면의 스크롤 기대값이었고, 1개는 복구한 비율 입력 방식을 다음 대상에 이어 주지 못하는 문제였다. 전자는 각 행·추가 버튼의 본문 스크롤 접근성과 footer 가시성을 검증하도록 갱신하고, 후자는 완료 시 복구된 입력 방식도 draft에 반영하도록 수정했다.
- 최종 `npm run check:ci`: harness·타입 검사 및 146개 파일의 단위 테스트 1,327개 통과.
- 최종 `npx playwright test tests/portfolio.spec.ts tests/account-workspace.spec.ts --grep '(?i:portfolio)'`: 65개 통과. 저장 실패·충돌·오프라인 잠금·Community에서 가져오기·새로고침 후 미완료 비율 복원 포함.
- 390·768·1280px 비율 입력/환산 금액과 샘플 복귀 화면을 캡처해 직접 확인했다. 기존 390×600·10개 대상·200% 확대·focus/44px target·overflow 회귀도 통과했다.
- 로컬 production build는 테스트 Supabase 설정으로 `npx vite build`를 실행했다. 실제 배포는 저장소 Pages workflow의 운영 설정을 사용하며 PR checks와 해당 workflow 결과에서 확인한다.
- 문서 4개의 상대 링크와 `git diff --check`를 확인했다. 변경이 Portfolio UI에 한정되어 다른 앱 전체 E2E 및 DB migration 검증은 추가 실행하지 않았다.
